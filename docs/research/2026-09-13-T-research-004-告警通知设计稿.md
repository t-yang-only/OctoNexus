## 1. 事件源盘点（全部现成，只缺"订阅者"）

| # | 事件源 | 位置 | 现状 | 告警可订阅 |
|---|--------|------|------|-----------|
| E1 | 分组变更/删除 | `handlers/group.go publishGroupEvent`（SSE） | 只推前端 | 异常删除、成员被清空 |
| E2 | 路由状态变化 | `relay/route.go publishRouteLocked`（SSE） | 只推前端 | 进入冷却、亲和切换、成员耗尽 |
| E3 | 请求终态 | `relay/state.go`（status success/failed/canceled） | 只推前端+记统计 | 连续失败率超阈值（窗口计数） |
| E4 | 渠道健康 | 无（R-quota-001 的 P5 产出） | 缺 | 余额低于阈值、探测失败/恢复 |
| E5 | 上游目录变化 | 无（P3 产出） | 缺 | 公告/下架/价格变化（指纹触发） |
| E6 | 价格同步失败 | `price.UpdateLLMPrice`（仅 log.Warn） | 缺 | 同步失败（供 R-route-001 数据新鲜度） |

E1–E3 已有 SSE 广播机制：**告警订阅者 = 第三种消费者**（除前端 SSE 外），
在 server 侧直接订阅 channel，不走 HTTP。

## 2. 通知渠道抽象（`internal/notify/`，先 webhook+smtp）

```go
// notify.go
type ChannelType string
const (
  ChannelWebhook ChannelType = "webhook" // POST JSON，模板变量渲染
  ChannelSMTP    ChannelType = "smtp"     // 标准库 net/smtp
)
type Channel struct {
  ID, Name string
  Type     ChannelType
  Enabled  bool
  Settings json.RawMessage // webhook:{url,secret,template}; smtp:{host,port,user,pass_ref,to}
}
type Alert struct {
  Title, Message, Severity, Status string
  Source     string // E1..E6
  TargetName string
  Values     map[string]string // 模板变量：balance/quota/health/changeTitle/changeUrl/…
  OpenedAt   time.Time
}
type Notifier interface {
  Send(ctx context.Context, ch Channel, a Alert) (string, error)
  DryRun(ctx context.Context, ch Channel) (string, error) // 发送前真实测试
}
```

- 模板变量与 api-monitor 对齐（`{{title}} {{severity}} {{targetName}} {{balance}} {{changeUrl}}…`），
  前端规则页可直接复用其 README 的变量表。
- 密钥（smtp 密码、webhook secret）走 R-sec-001 的 AES-GCM 存储。

## 3. 规则存储 schema（gorm，与现有 Setting 风格一致）

```go
type NotifyRule struct {
  ID        uint   `gorm:"primaryKey"`
  Name      string `gorm:"unique;not null"`
  Enabled   bool
  Scope     string // global|channel|group|apikey（先做 global+channel）
  Condition string // balance_below|quota_below|health_abnormal|cooldown_entered|fail_rate_above|content_changed|sync_failed
  Threshold float64
  WindowSec int    // fail_rate 等窗口类条件的统计窗口
  ChannelID string // 绑定的通知渠道
}
type NotifyEvent struct { // 去重/收敛：同 rule+target 在 CooldownSec 内只发一次
  ID uint `gorm:"primaryKey"`
  RuleID uint `gorm:"index"`
  Target  string
  LastSentAt time.Time
}
```

- 评估点：`task` ticker 每分钟跑一次规则（读内存统计+op 缓存，不碰转发热路径）；
  E2/E4 这类瞬时事件走订阅直发 + `NotifyEvent` 收敛。
- 管理 API：`GET/POST /api/v1/notify/rules|channels|test`（admin 端口，`middleware.Auth`），
  前端在 setting 下加"通知"页（复用 shadcn 表单模式）。
