## 1. litellm 策略精读（`reference/litellm/litellm/router_strategy/`）

litellm 的策略是"**日志钩子记指标 + 选路函数读指标**"：每个策略一个 `CustomLogger` 子类，
在 `log_success_event` 里按 `{deployment}:{minute}` 粒度写计数到 `DualCache`（内存+Redis），
选路时读回打分。octopus 是单进程，`internal/utils/cache` 分片内存即可替代 DualCache。

| 策略文件 | 指标 | 选路逻辑 | 可移植性 |
|---|---|---|---|
| `lowest_latency.py`（文件头注释实为 latency） | 响应耗时（流式按首 token） | 挑期望延迟最低 | ★高 —— octopus relay 每次请求已有 `Duration` |
| `lowest_cost.py` | `cost_map:{group}:{id}:{minute}` token 累计 | 挑单位 token 成本×近期用量最低 | ★高 —— `price` 表 + `ChannelModelStats` 现成 |
| `least_busy.py` | `{group}_request_count:{id}` 在途计数（TTL 1h） | 挑在途最少 | ★高 —— state.go 已知 running 请求，按成员分组计数 |
| `lowest_tpm_rpm_v2.py` | 分钟级 TPM/RPM（redis.incr+mget） | 挑 TPM/RPM 最低 | 中 —— 需分钟窗口计数器 |
| `tag_based_routing.py` | deployment tags | 按请求 tag 匹配子集再策略选 | 中 —— octopus GroupItem 无 tags，需加字段+migration |
| `adaptive/complexity/quality/router` | LLM 分类请求复杂度/质量 | 模型分级路由 | 低 —— 个人网关过重，不建议 |

### 冷却（`router_utils/cooldown_handlers.py`）
- 核心差别：litellm 按**失败率阈值**（`DEFAULT_FAILURE_THRESHOLD_PERCENT` + 最小请求数）进入冷却，
  octopus 按**固定尝试次数耗尽**（`MemberMaxAttempts`）进入冷却。
- litellm 按**异常类型区分容忍度**（`ContentPolicyViolationErrorAllowedFails`…
  `RateLimitErrorAllowedFails` 共 9 类独立计数器）；octopus 当前所有失败同等对待。
- octopus 已有而 litellm 无：**亲和**（failover 成功后粘滞）——保留。

## 2. pickGroupItem 扩展设计稿（`internal/relay/route.go`）

```go
// GroupMode 新增（model/group.go；binding oneof 同步；migration 默认 failover 保持行为）
GroupModeLowestCost    GroupMode = "lowest_cost"
GroupModeLowestLatency GroupMode = "lowest_latency"
GroupModeLeastBusy     GroupMode = "least_busy"

// GroupRelayConfig 新增（零值=关闭，保持旧行为）
FailoverOnStrategy bool // 策略模式下无健康成员时是否回退 failover 顺序重试
StrategyWindowSeconds int // 指标滑动窗口秒数，默认 300

// internal/relay/strategy.go（新文件）
type memberMetrics struct {
  costPerToken float64 // price 表 + 最近用量加权
  avgLatencyMs float64 // 成功请求的 Duration 滑动平均
  inFlight     int     // 当前 running 且 TargetItem==本成员
}
func rankMembers(group, metrics) []GroupItem // 过滤冷却+不可用 → 按策略打分排序
```

- 三种策略共用"过滤→打分→排序→取首"骨架，打分函数各自独立，单测可直接覆盖。
- 指标写入点：`recordRouteSuccess/Failure` 旁路追加（不阻塞转发主路径）。
- 先做 `lowest_cost`（R-route-001 第一阶段）：价格已知、无需窗口统计，
  打分 = `unit_price × (1 + recent_fail_rate)`，失败率天然把坏成员排后。
