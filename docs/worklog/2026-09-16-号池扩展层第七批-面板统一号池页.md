# 2026-09-16 号池扩展层第七批：面板统一号池页

## 1. 这一批补的是"接口面没人用"的缺口

前六批把接口做得比较全了（统一视图 / 自描述 / 能力位放行的操作 / 批量 / 过滤排序分页 /
导出 / OpenAPI 文档），但**没有任何调用方**。这一批让面板当第一个吃自己狗粮的调用方：
加一页「号池」，直接消费 `/api/v1/pool/*`。

意义不只是"补个页面"：接口设计若只有自测脚本调用，很容易积累"看起来能用、用起来别扭"的地方
（字段名、分页口径、错误码语义、能力位与按钮的对应关系）。真接一遍，问题就暴露出来了。

## 2. 页面刻意不假设池子里有哪些后端

- 进页面先 `GET /pool/kinds` 拿"有哪些后端、各自声明了什么能力位"；
- 按钮是否出现/可点，由该后端的 `capabilities` 决定（没声明 `toggle` 就没有启停按钮，
  并给 `title` 说明"该后端未声明这项能力"）；
- 后端 tab 直接用适配器自己的 `title`；
- 条目行里的 `detail` 是适配器自定义字段，页面按 key/value 平铺渲染，不做字段白名单。

所以以后接入新的反代工具包，**这一页不用改** —— 这是"接口按自描述设计"的验收点。

## 3. 落地内容

- `web/src/api/pool.ts`：统一号池的客户端。类型与后端 JSON 一一对应；`poolQueryString`
  负责把筛选条件拼成后端认的参数名（`kind/q/provider/status/enabled/healthy/has_expiry/
  expiring_within/sort/desc/limit/offset`）；动作函数 `poolProbeEntry`/`poolRefreshEntry`/
  `poolSetEntryEnabled`/`poolSyncKind`/`poolBatch`；导出用链接直下（`poolExportURL`）。
- `web/src/components/modules/pool/index.tsx`：页面本体 —— 汇总卡（总数/启用/停用/健康/带错误/
  24h 内到期）、后端 tab、搜索（300ms 防抖 + 变条件回第一页）、状态筛选、列排序（点表头）、
  分页（total/scanned/returned 三个口径分开显示）、逐条启停/探活/刷新、行内详情展开、
  后端告警（`warnings` / `kind_errors` 一栏列出"哪个后端取不到数据"）。
- 接线：`stores/app.ts`（Page 联合类型 + NAV_ITEMS，图标 Boxes）、`lib/page-preload.ts`、
  `components/app.tsx`（懒加载 + 渲染分支）。
- 三语文案：`navbar.pool` + 新命名空间 `unifiedPool`（45 键 × 简/繁/英，落盘后 `json.loads`
  校验并断言键确实落在该命名空间里）。

## 4. 新增测试装置：面板静态资源套件（run_panel_asset_test.py，4/4）

前端要进二进制必须走「停实例 → `pnpm build` → `go build` → 重启」，漏一步的效果就是
"源码里明明有、打开面板却没有"，而后端套件全绿也不会发现。这条套件直接看**正在服务的产物**：
首页是 HTML 且带入口脚本引用 → 入口脚本真能下载（不是 404 空壳）→ 全部构建产物里有号池页标记
（`unifiedPool` / `/api/v1/pool/kinds` / `/api/v1/pool/entries`）→ 三语文案都在产物里。

它已经注册进 `run_all.py`（第 25 条）。第一条断言就此把它接到实例上：改了前端不重新构建，
矩阵会红，并在失败详情里写清"前端是否真的重建过"。

## 6. 说明与边界

- **面板视觉效果未经人工/浏览器验收**：这一轮由用户明确拒绝了浏览器自动化操作，
  所以"页面能被点开、数据显示正确"只有编译期 + 产物标记 + 接口契约三层证据，
  没有"人眼看到"这一层。要补的话，打开 `http://127.0.0.1:13303`（admin/admin）→ 左侧「号池」即可。
- 页面只读 + 单条动作；批量动作接口（`/pool/entries/batch`）已在后端具备，页面暂未用上
  （批量启停是个破坏性更大的操作，等确认交互再上）。
- 声明式适配器注册的安全边界仍是待用户拍板项，未动。
