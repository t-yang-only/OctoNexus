# 2026-09-20 「扩展」页与号池预留接口

## 做了什么

用户要的"软件内的软件、进一层子菜单做扩展配置"落地成面板上的一个一级页 + 页内子菜单：

- 新增前端页 `web/src/components/modules/extensions/index.tsx`：左侧子菜单三项，右侧对应面板。
  子菜单顺序即排查顺序：**插件**（我要接自己的反代工具）→ **采集凭据**（我要看到某家站点余额）
  → **号池适配器**（我要让号池认识新形态）。三者常互为因果（插件要出口、采集要反代、适配器要主机白名单），
  分成三个一级菜单会让人来回跳。
- 新增前端客户端 `web/src/api/extensions.ts`：把三类扩展的接口收在一处（插件 list/scan/start/stop/update/delete；
  采集凭据 CRUD/采集一次/开始登录/完成登录/清会话；适配器 list/templates/register/delete）。
- 接线：`stores/app.ts`（Page 联合类型 + NAV_ITEMS 加 Extensions + Puzzle 图标）、
  `lib/page-preload.ts`（懒加载入口）、`components/app.tsx`（lazy + 渲染分支）。
- 三语文案：`locales/{zh_hans,zh_hant,en}.json` 各加 `extensions` 命名空间（子菜单/插件/采集凭据/适配器）
  与 `navbar.extensions`。
- 文档 `docs/extensions/README.md`：三类扩展的入口、**号池预留接口全清单**（管理面 + 转发口只读通道）、
  声明式适配器的硬约束、每类扩展的不可违背点与诚实边界。
