# 2026-09-20 真实站点实测、余额口径修正与采集出口节点

## 做了什么

用户给了 8 家真实中转站账号，要求"先登录这些做接口测试和功能验证"，并要求**用代理、不要让真实 IP 被拉黑**。

1. **先架出口**：把用户给的订阅导进节点池（`pcnvp-主订阅`，46 个节点），同步内核分配端口 41069+，
   实测 40 个出口里 34 个可出网（香港/日本 IEPL）。此后所有站点探测与采集都从这些出口发出。
   （旧订阅的入口 IP 已全部 i/o timeout，属于服务侧过期，不是产品问题。）
2. **真实站点探测**：2 家是真 new-api（登录 200，令牌在响应体；读账必须 Bearer）、
   6 家是同一套 SPA 平台（`/api/v1/auth/login` + `/api/v1/user/profile`，其中 2 家挂 geetest/腾讯验证码）。
3. **三处修正**（见 `docs/collector/README.md`）：new-api 余额口径（原来算出 -375.8 USD 的负数）、
   新增 `ai-gateway` 模板族、反代登录捕获响应体令牌。
4. **采集出口节点**：`credential_sources.proxy_node_id` + `collector.RunVia` / `NewLoginProxyVia`，
   fail closed（节点不可用即拒绝采集，绝不静默直连）；面板每行一个出口下拉。

## 判据

- 单测：`internal/collector/templates_balance_test.go`（2 例：new-api/one-api 必须把 `data.quota` 当余额、
  不得声明 quota 规则、必须带 Bearer；ai-gateway 的端点/单位/字段与两种形态都能过装载门禁）+
  `internal/op/credential_source_egress_test.go`（4 段：建源落库、只改出口要落库、没给不清空、显式 0 改直连）。
  **变异自证**：修 `Select` 列清单之前，这条用例正是红的（读回 11 而不是 22）。
- 活体：8 家真实站点全部经出口节点跑通（uu6=12.60 USD、pipixia=1.394 USD、okai=0.82、
  cochacode=25.07、aiaaa=30.80、tohoqing=8.31；两家验证码站点如实失败）；
  绑不存在的节点 → HTTP 400 `采集出口不可用…请重新选择节点`；改绑后同一条凭据再采集正常。
- `go build ./...` / `go vet` 干净，`go test ./... -count=1` 全绿，`npx tsc --noEmit` 0 错。
