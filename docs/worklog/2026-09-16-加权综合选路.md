# 加权综合选路（weighted 模式）第一阶段

日期：2026-09-16　执行：dsh-local（NM-DS-018 / 台账 T-weight-001）
需求：R-weight-001（用户 2026-09-16「后续要增加包月 按次 余额 倍率 质量等不同的权重进行最佳的模型分配」）

## 1. 本阶段做了什么

把「什么更重要」从**代码里的固定口径**变成**可调的设置项**，先落地机制与默认值：

- 新模式 `GroupModeWeighted`（客户端把分组模式选 `weighted` 即启用）。
- 五个维度（都用**已经存在**的实时信号，不需要新增数据）：
  | 维度 | 信号来源 | 方向 |
  | --- | --- | --- |
  | 成本 | 价表 input+output（成员模型）| 越低越好 |
  | 质量 | 成员近期成功率样本 | 越高越好 |
  | 延迟 | 成员最近一次尝试耗时 | 越低越好 |
  | 在途 | 该成员此刻并发数 | 越低越好 |
  | 近期消耗 | 60s 窗口内的 token/请求量 | 越低越好 |
- 权重设置项（0..100，缺省即下面的保守默认值，**改动无需重启**）：
  `route_weight_cost=30`、`route_weight_quality=30`、`route_weight_latency=15`、`route_weight_busy=15`、`route_weight_load=10`。
- 归一化在**本次候选集合内**做（线性映射到 0..1 后按权重求和），所以权重可以跨渠道比较、不受量纲影响；
  代价是候选集合变化时相对分随之变化 —— 这是刻意的：选路本来就是「在当下这批成员里挑最好的」。
- 并列按 priority 再按 ID（同输入同输出，可测）。

## 2. 两条口径（都写进了代码注释）

1. **缺数据按乐观先验**：某成员在某维度没数据时记最好值（与 lowest_latency 的「无耗时按 0ms 参与」、
   quality_first 的「无样本按中性 1.0」同一哲学）—— 新成员先给一次机会，试出真相后分数自然变化，
   不会被已有指标的成员永久压住。若**全候选都没有该维度数据**，该维度对所有人同分（弃权），不影响排序。
2. **权重全 0** → 全员同分 → 退化为 priority 顺序（文档化行为，不是错误）。

## 3. 验证（**只用本地 mock，未打真实上游**）

单测 `internal/relay/weights_test.go` **7/7**：
- 成本权重全给成本 → 选最便宜的（哪怕 priority 最靠后）；
- 质量权重全给质量 → 「贵但稳」压过「便宜但常错」（**机制**证明：这正是需要用户拍板的取舍点，代码只保证权重真的生效）；
- 只有部分成员有数据 → 无数据者按乐观先验排在很慢的成员之前；
- 全程无数据 / 权重全 0 → 都退化为 priority 顺序；
- 冷却成员压队尾；全员冷却返回 `ErrNoEligibleMember`；全等数据按 priority/ID 定序。

活体套件 `scripts/api-tests/run_weighted_test.py` **4/4**（mock 上游）：
- T1 weighted 模式可建档并正常转发；
- T2 把延迟权重拉满（其余置 0）→ 第一次命中 priority 第一的慢成员（15.0s），第二次改选快成员（**0.0s**）；
- T3 权重全 0 → 退化为 priority 顺序（选回慢成员）；
- T4 越界权重（500）被拒绝（HTTP 400「route weight must be an integer between 0 and 100」）且不写入。

回归：全量矩阵（新增 weighted 套件，真实上游套件按门禁默认跳过）；`go build`/`go vet` 0；`go test ./... -count=1` 全绿；
`pnpm build` 通过（分组模式下拉里出现「加权综合」）。

## 4. 未做（下一阶段，需要新增渠道字段与迁移）

用户点名的 **包月 / 按次 / 余额 / 倍率** 四个维度，本仓库目前**没有存这些数据的位置**：

- 余额：只有配额扫描的归零停用（`QuotaAction` 审计 + `ChannelKey.Enabled=false`），没有「当前余额」的在线字段；
- 倍率 / 按次单价 / 包月额度与重置日：渠道配置里完全没有这些列。

要做需要：`ChannelConfig` 或新表加列（含 migration）→ 采集/填写入口（面板）→ 把四个维度接进 `weights.go` 的 `weightedSample`。
**三个取舍点仍留给用户**（设计稿 §10）：
① 默认权重怎么排（本阶段的保守默认已可改）；② 允许「贵但快」压过「便宜但常错」吗；③ 包月用尽时降权还是直接剔除。
本阶段把这三点都做成了**设置项**，所以无论用户怎么定，都不需要再改代码。
