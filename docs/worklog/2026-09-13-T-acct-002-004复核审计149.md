## 2. T-acct-002 发现的 bug 与修复（1 个）

- 现象：`sub2APIGet` 仅校验 2xx 即返回响应体，无内容校验。
  `Sub2APIPlatformQuotas` 以 `json.RawMessage` 原样透传，2xx 网关 HTML 错误页
  或空体会被当作"有效 quotas 数据"返回调用方。
- 对照口径：NM-CUR-146 已在 `ProbeToken` 落 anti-200-HTML；S2 读侧属同一健康监控
  链路（T-acct-003 消费），必须同口径。
- 修复：新增 `s2JSONBody`，`sub2APIGet` 在 1MiB 限读后做 JSON 有效性判定
  （空体/非 JSON 一律 `ok=false`）。Keys/Subscriptions 下游解析本就依赖 JSON 前提，
  行为不变；仅 quotas 透传路径的误判面被堵住。
- 回归：`TestSub2APIGetRejectsNonJSON`（HTML+空体两案例）、
  `TestSub2APIGetAcceptsJSONArray`（顶层数组透传不回退）。
