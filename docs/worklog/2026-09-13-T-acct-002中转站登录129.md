# T-acct-002 中转站用户登录读侧客户端（NM-CUR-129）

- 认领：`docs/agents/claims/2026-09-13-cursor-local-T-acct-002.md`；ledger T-acct-002 todo→doing
- 范围：只做读侧客户端（登录→会话→读取），纯函数 + `http.Client` 注入；
  不含 UI、不含定时任务、不含停用；不落库（凭据只经内存态调用）；
  不改现有转发链路；失败一律 `ok=false` 不阻断转发热路径（沿用 `FetchBalance` 口径）

## 1. 实现（`internal/health/` 新增两文件）

- `relay_account.go`（常量与形状）：
  - 端点常量：NA `/api/user/login`、`/api/user/self`；S2 `/api/auth/login`、
    `/api/keys`、`/api/subscriptions`、`/api/platform/quotas`；超时 30s（与 FetchBalance 对齐）。
  - 读侧形状：`RelaySelfSnapshot`（quota/used/remaining）、`RelayAPIKeySummary`
    （id/name/sk/status）、`RelaySubscriptionSummary`（id/plan/expires_at）。
- `relay_account_client.go`（客户端）：
  - `NewAPILogin`：账密登录 → `success:true` 校验 → 会话 cookie（cookiejar 内含于 client）。
  - `NewAPISelf`：带会话自查，额度字段宽容匹配复用 `ParseBalancePayload`（缺字段推导补齐）。
  - `Sub2APILogin`：邮箱密码 → token（顶层 `token` / `data.token` 别名宽容）。
  - `Sub2APIKeys`：对象 `{data:[...]}` 与顶层数组两种形状；行内 `sk`/`key` 别名兜底；
    `id` 兼容数字与字符串。
  - `Sub2APISubscriptions`：对象/数组两形状。
  - `Sub2APIPlatformQuotas`：上游无稳定 schema，`json.RawMessage` 原样透传。
  - 公共 `sub2APIGet`：bearer 注入 + 2xx + 1MiB 限读 + 30s 超时；client 为空时构造默认。

## 2. 测试（`relay_account_client_test.go` + `relay_account_shapes_test.go`，httptest 桩）

- NA：登录成功下发 cookie；错密码拒；自查三元组推导正确；无会话自查失败。
- S2：登录换 token；错密码拒；Keys 两形状 + 别名兜底 + 坏 JSON 拒绝；
  订阅对象形状；quotas 原样透传。
- 修复过程中的关键 bug：`sub2APIGet` 原实现对 `client==nil` 直接失败，
  与登录侧"为空则默认构造"不一致（S2 读侧无 cookie 依赖，测试传 nil 即触发）。
  已对齐登录侧行为，全绿。
