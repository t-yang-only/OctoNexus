# 号池扩展层第二批：生命周期操作（R-pool-ext-001）

日期：2026-09-16　执行：dsh-local（NM-DS-023）
上游：`docs/requirements/2026-09-16-号池扩展性-design.md`、`docs/worklog/2026-09-16-号池扩展层接口.md`（第一片）

## 1. 本轮做了什么

第一片把号池抽象成「适配器 + 统一视图 + 自描述」，但只有只读的三条接口。这一轮补**按能力位放行的生命周期操作**：

**可选能力接口（`internal/pool/ops.go`）** —— 能力位是"对外声明"，接口是"对内契约"，**两层都满足才放行**：

| 能力位 | 接口 | 语义 |
| --- | --- | --- |
| `get` | `Getter.Get(ctx,id)` | 取单条 |
| `probe` | `Prober.Probe(ctx,id)` | 探活/读配额；**失败也回条目**（探活的价值就是告诉你现在什么状态） |
| `refresh` | `Refresher.Refresh(ctx,id)` | 刷新凭据 |
| `sync` | `Syncer.Sync(ctx)` | 把条目物化到转发层（kind 级），产出通用 `SyncReport` |
| `toggle` | `Toggler.SetEnabled(ctx,id,bool)` | 人工启停 |

为什么两层都要：只查能力位会让"声明了但没实现"变成运行期崩溃；只查接口会让外部工具在调用前无法知道某个后端到底支不支持，只能试错。
所以缺能力位 → `ErrUnsupported`；声明了却没实现 → 同样 `ErrUnsupported`，但消息里点名 `declared but not implemented`。

**官方账号池适配器的实现**（全部复用既有 op，不新增表、不动选路）：
`get` ← 与统一视图同源（避免列表/详情两套口径）；`probe` ← `op.OfficialAccountReadUsage`；
`refresh`/`sync` ← `op.OfficialPoolSync`（sync 逐个服务商跑，一个服务商失败不影响另外两个）。

**新增接口**（Admin + Auth）：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/pool/entries/:kind/:id` | 单条详情 |
| POST | `/api/v1/pool/entries/:kind/:id/probe` | 探活/读配额 |
| POST | `/api/v1/pool/entries/:kind/:id/refresh` | 刷新凭据 |
| POST | `/api/v1/pool/entries/:kind/:id/enable` \| `/disable` | 启停（无 toggle 能力 → **501**） |
| POST | `/api/v1/pool/kinds/:kind/sync` | kind 级同步 |

**错误映射就是接口契约**（外部工具靠它分支）：未知 kind → 404；条目不存在 → 404；
没这项能力 → **501**（不是 400/403：这不是参数错也不是权限问题，而是后端没这个能力）；其余 → 502。

## 2. 验证

- 单测 `internal/pool` **10/10**（新增 4 例）：未知 kind 五种操作全拒；只声明 `list` 的适配器写操作全拒；
  **声明了却没实现**要报明确原因而不是崩溃；五种能力正常路径 + 条目不存在；四种操作 panic 全兜成错误。
- 活体 `run_pool_api_test.py` **14/14**（新增 6 例）：
  P7 详情可读且同源、P7b 详情不回显凭据、P8 不存在条目 404、
  **P9 探活失败是干净失败**（夹具凭据是探针串 → 解密即失败、不发任何真实请求，接口回 502 且带明确 message、不泄漏探针、不崩栈）、
  **P10 未声明的能力位回 501** 并点名 `toggle`、P11 未知 kind 同步 404。
- 全量矩阵 23 套件，退出码 0；`go build/vet` 0。

## 3. 刻意没做的两件事

1. **没给官方账号池声明 `toggle`**：仓库里没有"渠道凭据级启停"的现成 op，账号可用性由同步逻辑按状态收敛。
   与其假装支持，不如让接口明确回 501 —— 这正是能力位存在的意义。等真正需要人工启停时再补 op 并声明。
2. **活体套件没有真跑 official 的 sync**：那会给实例建「官方账号池-&lt;provider&gt;」渠道，属于对用户数据的写副作用。
   同步行为由单测覆盖；等有专门的清理流程或用户明确要求时再补活体验证。
