## 1. 模型（`internal/model/official_account.go`，新增）

- `OfficialAccount`：`Provider(openai/gemini/claude)` + `ExternalName` 同服务商内唯一；
  `Status(pending/active/expired/revoked/error)`；`AccessCipher/RefreshCipher` 均为
  `json:"-"` 不出 JSON；`ExpiresAt/PlanTier/Window5H/Window7D/Healthy/LastCheckedAt/LastError`。
- 请求形状：`OfficialAccountCreateRequest{provider}`（发起）；
  `OfficialAccountCallbackRequest{account_id, one_time_code, state}`（回调/扫码确认，
  一次性凭证换取后即丢弃不落库）。
- `ValidateOfficialAccountProvider`：三类外拒绝。

## 2. 设计（接入流程，待 T-pool-002/T-acct-003 消费）

1. `POST /api/v1/account/official/authorize`（发起）：建 pending 行 + 签发
   `state`（防 CSRF，绑定账号主键+过期）→ 返回官方授权链接（各 provider 授权端点+PKCE）。
2. 回调/扫码确认：`one_time_code` 换 token → `AccessCipher/RefreshCipher` 加密落库
   （密钥走环境变量/密钥服务不落库，口径关联 R-sec-001/U-sec-001）→ 状态 active。
3. 读取：套餐档位/健康/5H7D 窗口回填 `PlanTier/Window5H/Window7D/Healthy/LastCheckedAt`；
   失败写 `LastError` + 状态 error/expired，不删行。
4. 账号→渠道建模（T-pool-002）：官方账号映射为渠道凭据（`ChannelKey` 形态复用），
   凭据解密只在转发构造出站请求时内存态进行。
5. 安全红线：`one_time_code`/明文 token 绝不落库、不进日志；state 校验失败拒绝；
   管理员权限才能发起/确认；密钥轮换走 T-sec-001 用户侧流程。
