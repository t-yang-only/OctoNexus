# 参考仓库要求全量合并收口说明

本轮依据 `docs/requirements/2026-09-13-渠道监控与负载均衡.md`、`2026-09-13-简洁监控约束.md`、`2026-09-13-new-api模型调用分析看板.md`、`docs/research/2026-09-13-参考仓库对标研究.md`，将此前仅登记/研究、但未实际合并的能力落入 octopus 原有 Go + React 架构。

## 已合并

- `UsageHourly` 分模型×渠道×小时用量桶，24h/7d/30d 查询，180 天保留清理；首页模型监控增加时间窗切换，保持单块简洁布局。
- `route_balance_enabled` 加权轮询设置已补齐启动注入和设置页热切换。
- 余额扫描周期、余额告警阈值已进入设置页。
- 新增告警 Webhook：余额低于阈值、额度归零自动停用均推送 JSON；Webhook 地址设置和 http/https 校验已加入设置页。
- API Key 增加 RPM/TPM 字段、滑动窗口限流、转发端 429 + Retry-After；设置页增加配置输入，0 表示不限。
- 三语文案同步：en / 简中 / 繁中。

## 明确保持的简洁/安全口径

- 不新增复杂监控导航页，监控继续挂在首页原有分析区块。
- 不引入 Redis、独立 worker、多用户计费等参考仓库重型架构。
- OAuth/Key/备份等敏感数据不回显；Webhook 只发送事件元数据，不发送密钥。

## 仍需真实环境配置

- Webhook 地址需要在设置页配置后才发送告警。
- RPM/TPM 需要对具体 API Key 设置非 0 值才启用。
- 真实 OAuth provider client id、redirect URI 和线上 key 轮换仍需部署环境提供，代码无需再改。
