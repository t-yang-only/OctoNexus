设计要点：

- **不落凭据**：mock 落盘前把 `Authorization` / `x-api-key` 换成 `bearer:<sha256 前 12 位>` 指纹，
  既够区分"用了哪把凭据"，又不把内容写进文件；运行期产物（`requests.jsonl` / `real_logs.json` /
  `display.cjs` / `mock.log`）由本目录 `.gitignore` 排除。
- **端口/路径全部 env 可覆盖**：`OCTOPUS_ADMIN_URL` / `OCTOPUS_RELAY_HOST` / `OCTOPUS_RELAY_PORT` /
  `OCTOPUS_MOCK_BASE` / `OCTOPUS_MOCK_PORT` / `OCTOPUS_DB` / `MOCK_SLOW_SECONDS`。
- **快速失败**：实例没起、mock 起不来、mock 日志写到了别处，都在开跑前报错并给出处置办法，不再跑一半失败。
- **汇总口径统一**：每个套件末尾打印 `NAME total=N pass=N fail=N`，运行器据此汇总并对未识别汇总行的套件明确标注。

### 搭测试过程中修掉的 5 处脚手架问题（都不是产品缺陷）

| # | 现象 | 根因 | 处置 |
|---|------|------|------|
| 1 | 4 个套件报 `FileNotFoundError: requests.jsonl` | 端口上还跑着早先手工在 `%TEMP%` 起的 mock，它把请求日志写在别处 | 运行器加预检：探针请求后日志文件必须增长，否则报错并提示停掉旧 mock |
| 2 | `lossless` 建 fixture 渠道 500（`channels.name` 唯一约束） | `/channel/list` 分页时找不到已存在渠道，误判为"不存在" | 存在性检查再用 `/channel/stats` 兜一次 |
| 3 | `quality` 冷启动用例假失败 | 成员样本窗口 300s 随进程存活，同一实例连跑时第 1 次请求已是暖态 | 断言改成识别冷/暖态并写明观测态，真正的判据（不反复撞已知坏成员）不变 |
| 4 | `failover` 用例 C/D 假失败 | 成员冷却存在进程内分组路由状态里，跨轮次残留 → "第一次尝试必撞慢成员"的前提失效 | 套件开跑前把相关分组冷却压到 3s 并等过它（`reset_cooldowns` + `wait_cooldown`） |
| 5 | `stats` 两条断言时好时坏 | ①库历史累计超一页（total=247 > 首页 200）却要求 `total == 页大小`；②用量桶是内存增量桶、按周期落库，与逐请求即写的 `relay_logs` 在同小时内只满足不等式 | ①改为页级不变式（无重复、全为终结状态）+ 明细写明是否整表校验；②判据改为 `usage ≤ relay_logs`（抓翻倍），差值写进明细 |

另外修了运行器自身两处：`parse_summary` 解包（正则两组命中）与子进程输出按 UTF-8 解码
（GBK 控制台下中文断言会让汇总行读取失败）。

## 二、谷歌号池与 GPT 号池：统一到同一个号池视图

**先说清楚"合并"合到什么粒度。** 号池后端本来就是按 provider 泛化的（`OfficialPoolSync(conn, provider)`
对 openai/gemini/claude 同一套实现，各建一条 `官方账号池-<provider>` 渠道）——渠道必须分开，
因为三家上游地址与鉴权互不通用；**能合、也该合的是管理层**：一处看全、一处同步。此前缺的正是这个面：

| 层 | 改动 |
|----|------|
| 后端 DTO | `OfficialPoolStatus` 新增 `members[]`：逐账号给出 `account_id / external_name / status / expires_at / plan_tier / window_5h / window_7d / healthy / last_error / key_name / key_exists / key_enabled`——界面拿一个接口就能画出"哪个账号映射成了哪条凭据"，不必自己 join 两张表；**只回名称与启用状态，绝不回显凭据内容** |
| 后端实现 | `officialPoolMembers(accounts, keyByName)` 在两种情况下都回明细：有号池渠道时按账号名对齐凭据；尚无渠道时也回（`key_exists=false`），于是"有账号还没同步"与"根本没账号"在界面上能区分 |
| 前端 | 账号页新增第三个标签「账号号池」：Google(Gemini) / GPT(OpenAI) / Claude 三张卡片放在同一页，各自带账号数、启用凭据、模型、授权计数与「同步」按钮，顶部一个「同步全部号池」；每张卡片下列出逐账号映射明细与凭据状态（启用 / 已停用（账号失活）/ 尚无凭据（先同步））、套餐档位、5H/7D 窗口、过期时间；同步结果里有问题的服务商会把 notes 逐条显示 |
| 三语 | `pool` 段 17 个键 × en / zh_hans / zh_hant，并在 `accounts` 段加标签名 |

### API 层（`scripts/api-tests/run_pool_audit.py`，14 例）
覆盖：`/pool/list` 返回三服务商合并视图且带 `members` 明细；合成账号按 provider 归位；
未同步时标记「尚无凭据」；快照字段（套餐/窗口/状态）透传；`/pool/sync` 指定服务商只同步该家；

未登录 → 401；清理后合成账号不再出现。

> 本地没有真实官方账号（OAuth 需要真凭据），故本套件用**合成账号行**验证视图与契约；
> "账号 → 凭据内容"的物化语义由 Go 单测覆盖（那里有加密 helper 可造真实密文）。
> 合成账号密文留空，同步时会被记入 notes（"账号…无法取凭据，需要重新授权"）——这本身也是契约的一部分。

## 四、已知限制

- 号池合并只到管理层：三条号池渠道仍各自独立（上游地址/鉴权不同，合并成一条渠道在技术上不成立）；
