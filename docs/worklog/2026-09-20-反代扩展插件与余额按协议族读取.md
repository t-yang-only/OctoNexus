# 2026-09-20 反代扩展插件与余额按协议族读取

## 做了什么

### 1. 社区反代扩展插件（R-plugin-001，新功能）

**目标**：账号池形态千差万别，主仓不可能为每一家写适配器。把"把某个账号池变成 OpenAI 兼容接口"
开放给社区，octopus 只提供三件事：运行环境、全局隐秘代理、接进主链路。

- 新增 `internal/plugin/`：`manifest.go`（清单解析与 fail-closed 校验）、`registry.go`（目录扫描/落库/令牌）、
  `runtime.go`（端口池、进程托管、状态回写、自动注册渠道）、`env.go`（出口注入与出口解析）、
  `platform_{windows,other}.go`（隐藏窗口、进程树结束、HTTP 探测）。
- 新增表 `plugins`（模型 `internal/model/plugin.go`）：清单字段 + 运行期列（Port/Status/PID/ChannelID）。
- 新增管理面路由 `/api/v1/plugin/*`（全部 `middleware.Auth()`）：list / scan / 状态 / 更新 / start / stop / delete。
- 设置项：`plugin_port_start`(42000)、`plugin_port_end`(42999)、`plugin_default_egress_id`(0)、`plugin_http_hosts`(空)。
- `cmd/start.go`：`auto_start` 的插件随实例拉起（内核之后 3 秒，避免出口未就绪的假失败），
  关闭时逐个停止。
- 文档：`docs/plugin/README.md`（插件作者契约：目录结构、清单字段、注入的环境变量、接口约定、边界）。

**关键口径**：
- 出网是硬承诺：`egress=pool`（默认）时拿不到可用节点出口就**拒绝启动**，绝不静默直连真实 IP。
- 注入 `OCTOPUS_EGRESS_PROXY` + `HTTP_PROXY/HTTPS_PROXY/ALL_PROXY`（含小写），并强制
  `NO_PROXY=127.0.0.1,localhost,::1`（否则插件回调 octopus 也会绕出口）。
- 插件令牌（自动注册渠道的凭据）密文落库（AAD `plugin:token`），只经环境变量注入，任何出参不回显。
- 入口必须落在插件目录内（判据取"解析后仍在目录内"，`./sub/../run.py` 与 `run.py` 等价）。

### 2. 余额按协议族读取（R-balance-002 余项，依据用户提供的实测报告）

实测报告确认上游只有三类接口能读到余额，而它们各是一种协议：

| 协议族 | 路径 | 单位 | 本实例命中 |
| --- | --- | --- | --- |
| 自定义余额 | `GET /user/balance` | USD | apikey.fan（11 把 Key，账号级） |
| 用量+余额同接口 | `GET /usage` | USD | openagents |
| OpenAI Billing 兼容 | `/v1/dashboard/billing/subscription` + `usage` | 额度常占位、用量为美分 | pipixia、转转AI |
| new-api 站点管理 | `/api/user/self` | 点 | 需要控制台 access token，sk- Key 无权 |

- 新增 `internal/health/balance_probe.go`：`ReadBalanceAuto` 依次探测四族，返回最可信读数；
  失败时把"试过哪些路径、各自什么结果"合成一句话（`路径=结果`，控制在一行内不被截断）。
- 占位额度（1e6/1e7/1e8/1e9 或 ≥1e8）判为不可信：**额度不进总额，用量如实带出**，原因码 `quota_placeholder`。
- 新增 `BalanceRead.InCurrency`：区分"美元"与"new-api 的点"。聚合层据此决定是否按
  `balance_points_per_unit` 折算。
- `internal/op/quota.go`：`RecordChannelBalanceWithUnit` + `ChannelBalanceInCurrency`；
  `internal/op/balance.go` 按单位口径决定是否折算。

## 实测抓到的三个缺陷（都已修，都有判据）

1. **`PID` 被 GORM 命名策略拆成 `p_id`**：回写状态用原始列名 `"pid"` → `no such column: pid` →
   启动接口回 400，而插件**已经在后台跑着**、端口占着。修法：`gorm:"column:pid"`；
   并把"启动成功后回写失败"改成先停进程再报错（不留半托管状态）。
2. **美元被当成点再折一次**：apikey.fan 的 `{"balance":32.53}` 被点口径的宽容解析抢走 →
   聚合层除以 500000 → 面板显示 `6.5e-05`。修法：`parseGenericBalance` 先认钱的名字
   （balance/remaining/total_balance/balance_infos），再退回点口径。
3. **失败文案被截断**：探活失败文案写成 `路径→HTTP 404` 后超过 120 字上限，
   最后一条（OpenAI Billing）被切掉。修法：改为 `路径=404` 的紧凑形态。

## 验证证据

- 单测：`internal/plugin`（清单拒绝矩阵 8 例、默认值/归一化、占位符、出口注入、fail-closed 出口）、
  `internal/health`（三族解析 + 逐族探测链 + 占位额度只算用量 + 货币/点单位判定）、
  `internal/op`（`TestBalanceSummaryRespectsReadUnit`：货币读数不得再折算）；
  全仓 `go test ./... -count=1` 19 包全绿，`go build ./...` / `go vet ./...` 干净。
- 变异检查：把 `balance.go` 的单位分支改回"一律折算" → `TestBalanceSummaryRespectsReadUnit` 变红，
  且复现出线上那个 `6.506e-05`；把 `channel.go` 的 `proxy_node_id` 从 Select 名单删掉 →
  `TestChannelUpdatePersistsProxyNodeBinding` 变红。
- 活体（本地实例 33000/33001，`%TEMP%\octopus-dstest\verify_balance_and_plugin.py`，20/20 通过）：
  - 余额：已知余额渠道 0 → **2**，逐渠道 `apikey=32.53154022`、`openagents=76.723542`；
    原因归类 `{no_endpoint:10, quota_placeholder:2, unauthorized:1, unreachable:1}`。
  - 插件：扫描→绑定出口→启动（200，port 42001，egress `http://127.0.0.1:41001`）→自动注册渠道
    （channel_id=39，base_url `http://127.0.0.1:42001`）→停止回落 stopped。
  - 环境注入实证（读插件自己落盘的 `env-dump.json`）：`HTTP_PROXY=HTTPS_PROXY=http://127.0.0.1:41001`、
    `NO_PROXY=127.0.0.1,localhost,::1`、令牌已注入且不出现在接口出参里。
  - **出口实证**：插件用环境代理出网拿到的出口 IP（165.232.138.25）与节点探活结果**完全一致** ——
    插件没写一行代理代码，出口已经是节点。
