## 1. 测试装置

要把"客户端协议"与"上游协议"分开控制，就要把上游协议钉死：新建测试渠道 `DS-TEST-proto3`
（指向 mock 上游 `http://127.0.0.1:18099`），**同一个模型 `mock-good` 配三把凭据**，三条授权各给一个协议位：

| 凭据名 | 协议位 | 用途 |
|--------|--------|------|

| `pin-responses` | 4（OpenAI Responses） | 上游固定走 Responses |
| `pin-messages` | 8（Anthropic Messages） | 上游固定走 Messages |

三个分组各挂一条授权 → 3 客户端协议 × 3 上游协议 = **9 例**，另加 3 例同协议直通与 1 例流式，共 **13 例**。
脚本 `%TEMP%\octopus-dstest\run_lossless_tests.py`；mock 上游本轮补上了**请求体落盘**（`requests.jsonl`
新增 `body` 字段），断言的根据就是"上游实际收到了什么"。

## 2. 断言口径（"无损"= 不丢不改）

每个请求都带同一份语义载荷：`SYS-MARKER-1`（system/instructions）、`USER-MARKER-1` → `ASSIST-MARKER-1`
→ `USER-MARKER-2`（多轮顺序）、`max_tokens=321`、`temperature=0.25`、一个函数工具 `probe_tool`
（JSON Schema 带 `x` 字段）。逐例核对：

1. 四个文本标记**全在上游请求体里**，且三轮顺序与发送顺序一致；
2. max tokens 与 temperature **值相等**（各协议自己的字段名都认：`max_tokens` / `max_output_tokens` /
   `max_completion_tokens`）；
3. 工具名与 Schema 字段保留；
4. 客户端拿到的响应是**客户端协议的形状**（Chat → `choices[].message`；Responses → `object=response`
   + `output[]`；Messages → `type=message` + `content[]` + `stop_reason`），且携带**上游那份正文**
   （`mock chat ok` / `mock responses ok` / `mock messages ok`），即响应侧同样不丢内容；
5. **同协议直通**额外做逐字段相等：除 `model` 外每个字段的值都必须与客户端发的一模一样
   （`model` 由分组名映射成成员的上游模型名，属设计内映射，单独做正断言）；
6. 流式那一例（Anthropic 入 → Chat 上游出）要求 SSE 里能看到上游增量文本并出现终止事件。

## 3. 首轮结果：10/13，两类问题

**我自己的假阴性（已修测试）**：`Responses → Chat` 方向把 max tokens 映射成 `max_completion_tokens`，
原来只认 `max_tokens`/`max_output_tokens` 就误判成"丢了"——改后该方向 PASS。

**真·有损（已修产品）**：目标协议为 Responses 时 **`temperature` 不会出现在上游请求体里**——
`chat → responses` 与 `messages → responses` 两例实测 `温度保留=False(实际 None)`，而同协议
`responses → responses` 直通时它是在的（`temperature: 0.25`），说明丢失发生在**转换过程**里，
不是上游不接受该字段（Responses API 的 `temperature`/`top_p` 都是合法字段）。

### 修复

`internal/relay/upstream.go`：

- `conversionMiddleware` 增加 `clientBody`（客户端原始正文，`sendConverted` 里就地取）；
- `OnOutboundRawRequest` 在应用渠道参数之后调用新函数 `carryOverSamplingParams(clientBody, format, outboundBody)`：
  **只在目标协议是 Responses、客户端给了该键、上游没有该键**时补写 `temperature` / `top_p`；
  非 Responses 目标、客户端正文不是 JSON 对象、上游已有值、正文不是 JSON —— 一律原样返回；
- 补写用 `sjson.SetRawBytes(body, ":"+key, ...)`（与 `applyChannelConfig` 同款写法），并同步
  `request.JSONBody`，只增不改、不覆盖转换层与渠道覆盖写下的值。

新增单测 `internal/relay/upstream_params_test.go` 5 个子用例：缺值补回且其它字段一个不少、
上游已有值不覆盖、客户端没给的参数不凭空造、非 Responses 目标字节不变、非 JSON 正文 no-op 不报错。
