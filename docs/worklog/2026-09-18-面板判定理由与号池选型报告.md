## 1. T-decision-002：把判定理由放到界面上

上一轮的 `X-Octopus-Route` 与 `relay_logs.decision` 已经能让客户端和接口看到理由，但面板看不到——
排障时最常用的入口恰恰是日志页。本轮补齐三处：

| 文件 | 改动 |
| --- | --- |
| `web/src/api/log.ts` | `RelayHistoryItem` / `RelayLogOverview` 各加 `decision`（历史行必填、实时快照可选） |
| `log/display.ts` | `LogDisplayFields.decision` + 取值（**两个来源都直接透传后端同一份文本**，不在前端拼） |
| `log/store.ts` | `LogFieldName` 加 `decision`，出厂可见（与上游轮次一致） |
| `log/FilterBar.tsx` | 字段开关清单加一项 |
| `log/Item.tsx` | 单元格：`Route` 图标 + 等宽小字截断（完整值＝响应头那份） |
| `setting/System.tsx` | 新增 `relay_request_fault_action` 下拉（复用既有 `WeightSettingField`，两选项） |
| `api/setting.ts` | 键名映射 `RequestFaultAction` |
| 三语 locales | `log.filter.decision`（判定理由 / 判定理由 / Why this route）+ `setting.routing.requestFault{Action,Failover,Failfast}` |

口径上有一条刻意的克制：**前端不重新组装这句话**。判定文本是后端 `relay.Decision.Text()` 的唯一产物，
面板只显示它收到的字符串——前端一旦自己拼，就会出现"界面说亲和、响应头说顺序"的第三种说法。

判据：`npx tsc --noEmit` 0；eslint 在改动文件上无新增问题（`FilterBar.tsx` 的
`react-refresh/only-export-components` 报错在改动前就存在，属既有）；面板套件新增 **P12**
（判据标记：`requestFaultFailfast` / `relay_request_fault_action` / 三语 label）→ **PANEL 12/12**；
完整矩阵 **29 套 0 失败**（含 display 22/22、reallog 24/24、retry 12/12）。

## 2. T-pool-004：R-pool-003 号池管理选型报告补全

旧草稿（2026-09-13，32 行）的结论是"建议搁置"，两条理由（R1 冻结不含号池转发、W3#1 前置未过门）
现在都已不成立，用户又明确要求补全，于是按草稿自己列的 §2 大纲展开为全文
（`docs/requirements/2026-09-13-号池管理选型.md`）：

1. **候选清单**：6 个真实项目，统一字段（路线 / 登录协议 / 额度可见性 / 封号风险 / 维护活跃度 / 与本项目关系）。
   其中两条按红线**一票否决**并登记为反例（协议逆向类、批量注册 + 临时邮箱类）——它们技术上"能用"，
   但接进来之后风险与控制权都不在我们手里。所有来源都标注了 URL。
2. **合规红线**：官方 OAuth / 扫码授权；凭据密文落库（AES-256-GCM + AAD 绑服务商，已交付）；
   日志、导出、响应头绝不出现凭据（已有外部可观测判据）；不接逆向与批量注册；订阅拼车不做成出厂预设。
3. **并入映射**：逐项落到本项目对象——账号四件套（Channel/ChannelKey/ChannelModel/ChannelGrant）、
   号池统一视图（`pool.Kinds/Entries/Snapshot`）、余额与可用性（T-quota-001 接线 + 总余额 + 号池 summary/export）、
   面板与登录兜底。**唯一缺口是"会话级粘性"**（外部网关按会话线程固定账号的思路）：我们现在只有成员级亲和，
   要做会话级必须先定"会话标识"从哪来（请求头 / 首条消息指纹 / 客户端自报），本报告只登记方向、不擅自实现。
4. **推荐优先级**：OpenAI → Gemini → Claude（官方账号池）；第三方项目只作**只读**适配对象
   （先接余额/可用性这类只读信息，不接账号托管与自动签到这种"以你的身份对外动作"的能力）。

报告的后两节与 ⑩（号池扩展层四个边界）直接对接：① 声明式适配器安全边界、② 只读 APIKey 渠道、
③ 通用入口→凭据同步、④ 先接哪些工具包——本报告第 4 节已给 ④ 的初判。
