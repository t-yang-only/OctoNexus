# 授权矩阵按凭据实际支持的模型收敛（上游 #387）

上游 issue：**#387 [Bug] 多密钥模型列表不同时，协议全选会为不支持该模型的密钥创建授权**（JmPotato，2026-09-09，已关闭）。
本轮把它在本项目落地，并补上可反复执行的纯函数套件。

## 一、为什么算"本项目也有"

代码事实（改动前）：

- `web/src/components/modules/channel/FormGrants.tsx` 的三级授权格由同一个 `GrantCells` 渲染，
  三态统计与写入都是 `for (const modelName of models) for (const keyName of keyNames)` 全量置位，
  只按 `models × keyNames` 算 `total`，**完全不看某个凭据是否供得了该模型**。
- 同一渠道的多个凭据各自支持一部分模型是常态（issue 里就是一个供应商两个密钥，一个发 Gemini 系、一个发 OpenAI 系）。
- 授权表是转发时的派发依据：存下"model-a 可用凭据 B"，请求就会被派给供不了 model-a 的凭据，在上游失败。
- 而"每个凭据支持哪些模型"这份知识在本项目里**只存在于探测的返回值里**（`probe.ts` 的 `useModelProbe`
  拿到 `[{name, protocols}]` 后只并入 `models` 与 `grants`，用完即弃），所以界面此前无从判断。

## 二、改法

新增 `web/src/components/modules/channel/grants.ts`（零依赖纯函数，可单测）：

| 函数 | 作用 |
| --- | --- |
| `isPairSupported(index, 模型, 凭据)` | 该组合是否可分发生效；**没有探测记录的凭据一律放行** |
| `supportedKeyNames(index, 模型, 凭据名[])` | 某模型下真正可分发的凭据，批量勾选与分母都按它算 |
| `unsupportedPairs(index, 模型[], 凭据名[])` | 已知不可用的组合清单，保存前按它裁剪 |
| `recordProbe(index, 凭据, 模型[])` | 探测成功后记录该凭据的支持清单（替换旧结论；空清单不改判） |
| `declareModel(index, 凭据, 模型)` | 人工声明优先：手填模型不会被自己的探测结论锁死 |

落到界面的四处：

1. `ChannelFormState` 增加 `keyModels: KeyModelIndex`——**只用于收敛授权范围，不提交给后端**
   （`toChannelConfig`/`toChannelDetail` 都是显式构造载荷，天然不带它）。编辑既有渠道时为空：
   探测结论不随渠道保存，旧授权也不足以反推"某凭据支持哪些模型"。
2. `GrantCells` 的三态统计与写入都跳过不可用组合：计进去会让全选显示为"选不满"，写进去会存下无效授权；
   单组合格不可用时置灰并给出原因（`title`）。
3. 模型行的 `已授权/可用` 分母改成**可用凭据数**（供不了该模型的凭据不计入），否则一行的 3/3 是假的。
4. 提交前 `pruneUnsupportedGrants(state)` 再收敛一次：界面挡的是新勾选，这里兜住探测之前就已存在的旧组合
   （上游全量置位存下的正是这一类），**删掉的条数用 toast 提示**，不静默改动用户既有配置。
5. `probe.ts` 探测成功后把结果写入 `keyModels`；`addModel` 手填模型时同时 `declareModel`。

三语文案各加两条：`grantUnsupported`（该凭据不支持此模型）、`grantPruned`（已丢弃 {count} 条…）。

## 三、验证

新增纯函数套件 `scripts/api-tests/check_grants.js`（矩阵第 27 套，`node,esbuild`）：
由 `grants-entry.ts` 把界面真正跑的 `grants.ts` 与 `state.ts` 两条链路打成单个 cjs（`run_all.py` 的
`build_grants_cjs`），node 直接跑，**26 例全过**：

- 未知凭据放行、不裁剪（不拿"没探到"当"不支持"）；
- 探测结论按凭据隔离：`A 供 model-a` / `B 不供 model-a` / `A 不供 model-b` / `B 供 model-b`；
- 全选只落在可用组合：`unsupportedPairs` 恰好给出 `[["model-a","B"],["model-b","A"]]`，分母只数可用凭据；
- 保存前裁剪：四条被污染授权裁掉 2 条、合法组合的协议位不动、**未探测凭据的授权不被裁**；
- 提交载荷（`toChannelDetail`）里只剩两条有效授权——"保存时不落无效授权"的直接证据；
- 合法组合取消勾选后仍可再勾（判据只看探测结论，与当前授权无关）；
- 探测以实测为准且空清单不改判、模型名原样保留不裁剪空白（裁剪会造成"探到了却判不支持"）；
- 人工声明优先，无记录凭据不因声明建立限制。

产物侧：`run_panel_asset_test.py` 新增 **P8**（`grantUnsupported` 键被引用 + 三语文案），
面板 **8/8**——证明这一改动真的进了随二进制发布的产物，而不是只躺在源码里。

其余口径：`npx tsc --noEmit` 0；eslint 仅跑改动文件 exit 0；`go vet ./...` 0；`go test ./... -count=1` 12 包全绿；
完整矩阵 27 套 0 失败。

## 四、边界（如实记录）

- **判定依据只有探测**：没探测过的凭据不设限，所以"全选越权"在这类渠道上仍可能出现——但那时系统并不知道
  该凭据支持什么，硬拦会把手填模型和未探测凭据一起误伤。探测一次即生效。
- **保存时裁剪建立在探测结论上**：若某次探测因上游偶发故障少返回了模型，被删的授权会在 toast 里给出条数，
  可重新探测恢复；这也是选择"删 + 明确提示"而不是"静默保留"的原因（issue 的预期行为明确要求不为无效组合存储授权）。
- **未做浏览器端到端**：用户此前已明确否决把浏览器自动化验收提交进仓库，故界面侧证据是
  "纯函数逐边界 + 产物标记"，不是点击复现。
- 仍待用户拍板的只剩 **400 类错误的取向**（保留故障转移 vs fail-fast 回上游原文）。
