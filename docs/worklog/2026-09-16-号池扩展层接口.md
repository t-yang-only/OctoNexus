# 号池扩展层第一批接口（R-pool-ext-001 第一片）

日期：2026-09-16　执行：dsh-local（NM-DS-022）
设计：`docs/requirements/2026-09-16-号池扩展性-design.md`

## 1. 本轮做了什么

用户要求「号池加入高度扩展性，基于已有的开发大量 API 接口，后面好做各种反代工具包的扩展」。
第一片落在**抽象层 + 只读接口**上，新增包 `internal/pool`：

- **Adapter 接口 + Registry**：一种号池后端 = 一个适配器；注册期校验（空 kind / 缺 list 能力 / 未知能力位 / 重复 kind 都报错）。
- **能力位（Capability）**：`list/get/probe/refresh/toggle/provision/revoke/sync` —— 适配器显式声明能做什么，接口层与外部工具据此决定可用操作。
- **自描述（AdapterInfo + FieldSpec）**：title、能力位、字段说明；凭据类字段带 `secret: true`，用来告诉外部工具"别指望接口回显"。
- **统一视图（Entry）**：与后端无关的一行（kind/id/name/provider/status/enabled/healthy/plan_tier/expires/labels/detail），官方账号池/中转站/未来工具包都投影成同一张表。
- **内置官方账号池适配器**：投影既有 `op.OfficialPoolStatusList`，只读、不新增表、不动选路 —— 真正做到"基于已有的"。
- **错误隔离**：单后端失败进 `warnings[]`，HTTP 仍 200；适配器 panic 由 `safeEntries` 兜成 warning（适配器是扩展点，将来是别人写的代码）。

新增三条接口（Admin 端口 + Auth 之后）：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/pool/kinds` | 已注册后端 + 能力位 + 字段说明（外部工具包的自发现入口） |
| GET | `/api/v1/pool/entries?kind=` | 统一视图（kind 留空=全部） |
| GET | `/api/v1/pool/stats` | 聚合计数 |

## 2. 验证

- 单测 `internal/pool/pool_test.go` **6/6**：注册校验（4 类坏适配器 + 重复）、kind 过滤与未知 kind、单后端失败隔离、计数、内置适配器能力位与 secret 标记、**适配器 panic 变 warning**。
- 活体 `scripts/api-tests/run_pool_api_test.py` **8/8**：
  P1 自描述（capabilities ⊇ {list,get,probe,refresh,sync}、access_token 标 secret）；
  P2 统一视图列出 3 条夹具账号；**P2b 凭据探针**（往库里写一个可识别串，断言它没出现在任何接口响应里）；
  P2c 账号→凭据映射状态可读；P3 kind 过滤；P4 未知 kind 明确 400 `unknown pool kind`；
  P5 聚合计数与条目一致；P6 未登录 401。
- 全量矩阵 **23 套件**（新增 poolapi），退出码 0；`go build`/`go vet` 0。

## 3. 过程中修掉的两个自己的坑

1. **类型名与方法名撞车**：`type Stats` 与 `func Stats()` 在同一个包里不能共存（Go 不允许类型与方法同名）→ 方法改名 `Snapshot(ctx) Stats`。
2. **单测环境没有数据库**：内置适配器要读 DB，单测里枚举全部 kind 会走到 op 层 panic → 加了 `withoutBuiltin(t)` 辅助（临时摘掉内置适配器再装回）。
   顺带把这条经验产品化：`safeEntries` 让**生产环境**里适配器 panic 也只表现为一条 warning。
