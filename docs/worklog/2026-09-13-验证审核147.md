## 1. 确认 bug（已修）：`ParseBalancePayload` 仅"已用"单字段时推导出负剩余

- 位置：`internal/health/balance_parse.go`（T-quota-001，117 产物）
- 问题：原推导顺序为"剩余缺失→`remaining=quota-used`；总额缺失→`quota=used+remaining`"。
  当 payload 只有 `used`（或 `used_quota` 等别名）而无总额/剩余时，第一推导得到
  `remaining = 0 - used < 0`，且函数返回 ok=true。
- 危害：负剩余会被下游 `QuotaZeroStop`（`remaining <= QuotaZeroThreshold`）当作
  已归零，**误停用健康渠道的全部凭据**——T-quota-002 链路的安全前提被破坏。
- 修复：在推导前增加守卫 `if !qOK && !rOK { return ok=false }`（只剩已用无从推知），
  并补 2 个分支单测（used-only 拒绝 / balance-only 推导通过）。
- 附带：新单测中 4 处 `t.Fatalf/Errorf` 格式串动词数与参数数不匹配（3 动词 4 参数）
  导致 vet 失败，一并修正为 4 动词。
