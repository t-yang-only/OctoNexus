- 需求：生成渠道模型时，必须自动创建分组，分组名规则为 `渠道名/模型名`

## 目标

渠道创建/更新提交模型后，自动补齐 `渠道名/模型名` 分组：
幂等可重入，已存在只补缺失成员；不覆盖人工改过的模式与 Relay 参数；
新建分组默认故障转移；创建后分组立即可被 `/v1/models` 与转发看到。

   `addChannelModelPrices`）、`internal/server/handlers/group.go`（分组 CRUD + SSE 事件）、
   `internal/relay/route.go`（手动/故障转移选路，读 `group.Items` 按优先级）
4. 前端：`web/src/api/channel.ts`（创建后只失效 `channels` 与 `models`，更新/删除/启停才连带失效 `groups`）、

## 结果

- 新增自动分组：每个渠道模型在有授权时对应一个 `渠道名/模型名` 分组，
  成员为该模型全部授权（按 grant ID 排序后依次给 priority），多凭据即多成员故障转移
- 幂等：重复提交同名分组只补新授权成员；人工改模式/Relay 参数会被保留；
  无授权模型跳过（不建空分组）；模型名去重去空；渠道改名后旧分组保留、新名分组新建（由人工归档旧名）
- 可见性：`ChannelCreate` 补上缺失的 `groupRefreshCache`，新建渠道的自动分组立即进 `/v1/models` 与转发；
  前端 `useCreateChannel` 原不失效 `groups`，但分组页按 `refetchOnMount: 'always'` 重拉，影响仅为创建后不自动弹新行，可接受

  未跑 `gofmt/go vet/go build/go test`，仅做 Python 静态文本检查 + 人工逐段复核；

- 仓库零 `*_test.go`，本次未新增 Go 单测；建议后续补 sqlite 内存库的
  `ChannelCreate → GroupList` 断言（建渠道→查 `渠道名/模型名`→重提交幂等→删模型行为）
- 渠道改名产生孤儿旧分组：旧 `渠道名/模型名` 分组保留（成员变不可用），需人工删除；
  可选后续在改名时自动重命名纯自动分组（需先标记自动来源）
- 模型移除不删自动分组：`syncChannelModels` 删模型会级联删授权，
  但自动分组本身保留变空组（避免误伤人工复用）；可选后续加“空自动组随删”开关
- 自动分组无来源标记：目前靠 `failover + 默认 Relay 参数 + 渠道名/模型名` 推断，
  后续若要“改名自动跟随/空组自动回收”，需给 `groups` 加 `auto_created` 列 + 迁移
