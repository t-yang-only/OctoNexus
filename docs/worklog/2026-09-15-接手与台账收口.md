## 2. 交付一：T-pool-002 官方账号号池转发（凭据侧物化）

口径与 `docs/requirements/2026-09-14-pool-002预研.md` §1 一致，且不新增模型表：

| 官方账号侧 | 号池映射 | 实现 |
|---|---|---|
| 一个服务商 | 一个号池渠道 `官方账号池-<provider>` | `OfficialPoolSync` 取或建，已存在则原样保留（不覆盖操作者改过的地址/路径） |
| 一个 OAuth 授权 | 该渠道下一条 `ChannelKey`，Key=解密后的 access token | 凭据名=账号 `ExternalName`，同步幂等 |
| 账号可用性 | 该 `ChannelKey` 的 `Enabled` | 非 active（pending/expired/revoked/error）只停用凭据、不删账号行，重新授权后同一条凭据被重新启用 |
| 登录态过期 | 临期自动刷新 | 距到期不足 5 分钟且带刷新凭据时换新 token，密文与过期时间一并落库；余量充足不刷（官方刷新会轮换凭据） |

- 新增 `internal/op/official_pool.go`：物化、停用、刷新、状态快照；**不引入新表、不改选路、不动协议转换**——
  选路复用 T-route-002 的加权轮询，协议位复用 T-proto-001 矩阵口径。
- 模型与授权**不由本模块臆造**：官方模型名与协议位只能由既有「拉取模型 + 三协议实测」流程给出真实结论，
  故号池渠道建好后仍走渠道编辑页拉取；`OfficialPoolSyncResult` 回显该渠道已有 models/grants 数供核对。
- 新增 `internal/model/official_account.go` 三个 DTO（同步请求/同步结论/状态快照）。
- 新增两接口（Admin 端口 + Auth 权限门，口径沿既有 official 组）：
  `POST /api/v1/account/official/pool/sync`、`GET /api/v1/account/official/pool/list`。
- 故障降级：单条账号解密失败/无刷新凭据只记入 `Notes` 并跳过，**绝不覆盖既有可用凭据**；
  一家服务商出错不吞掉其余服务商的同步结果。
