# 2026-09-20 内置站点模板与「账号密码登录看余额」

## 用户诉求

「加入可以通过输入账号密码登录一下项目的网址参考到余额调用和剩余次数和订阅等，如果需要验证码就可以走反代理方向
抓取验证码或者通过号池监控的包来进行上传」，并给出四类上游的定位：new-api（当前主流）、one-api（存量最多）、
sub2api（订阅拼车）、LiteLLM Proxy（海外/企业向）。

## 做了什么

把这四类站点的登录/查账惯例做成**内置模板**，面板上"选类型 + 填网址"即可生成一份可直接装载的采集包：

- 新增 `internal/collector/templates.go`：`Templates()` 列出 4 类 × 2 形态（form / interactive）；
  `BuildTemplate(kind, baseURL, mode)` 生成包并**先过一遍装载门禁**（生成即校验），主机白名单由用户填的网址推导。
  单位写死在模板里：new-api / one-api = 点，sub2api / litellm = 美元。
- 新增路由 `GET /api/v1/collector/templates` 与 `POST /api/v1/collector/templates/render`（管理面 middleware.Auth）。
- 面板「扩展 → 采集凭据」新增 `TemplatePicker`：站点类型下拉（带定位说明与端点）、登录形态下拉
  （账号密码直连 / 反代登录页）、网址输入、套用模板；套用后自动填好表单（反代形态自动落成 login 形态的源，
  面板就会给"开始登录/完成登录"）。三语文案同步。
- 文档 `docs/collector/README.md` 增加模板一节（端点表、两种形态的区别、四条硬口径）。

## 判据

- 单测 `internal/collector/templates_test.go`：8 条模板全部过装载门禁、hosts 只含所填主机、请求地址不越界、
  interactive 版本不带 API 登录步骤、单位表、坏输入被拒、无 scheme 网址补全。全仓 `go test ./... -count=1` 20 包 ok。
- 活体 `%TEMP%\octopus-dstest\verify_site_templates.py` **10/12**：类目清单 4 类 × 2 形态、生成 form 包的登录/读账端点
  指向所填主机、interactive 包不带登录接口、坏输入 400、用模板包创建采集凭据、**错密码回 unauthorized（不假成功）**；
  两条 FAIL 是脚本自身的期望取值问题（见下）。
- 活体 `%TEMP%\octopus-dstest\verify_points_conversion.py`：new-api 形状的桩站返回 `quota=1500000 / used_quota=500000`
  ⇒ 渠道余额 **2.00 美元**（1,000,000 点 ÷ 500,000），渠道被标为已知余额 —— **点数折算这一跳是通的**。

  实际该字段存的是**原始读数**、单位随 `units` 显示；折算发生在落到渠道时）。产品行为正确，脚本已如实保留。
