# 2026-09-20 账号级采集凭据（登录反代 + 采集包）

## 要解决的问题

用户要两件事一起做：① 把中转站**反向代理成临时地址**，他在这里登录（含验证码）拿到站点凭证，
然后就能看到余额与用量；② 或者把**逆向出来的登录/查账接口做成"包"**，装进软件后长期自动监控。
另外要求号池留更多预留接口、面板要有可进入的子菜单做扩展配置。

现状（本轮实测）：15 家启用渠道里 12 家站点根本没有余额接口（404），3 家要站点面板访问令牌
（sk- Key 只拿到 401/403）。所以"账号级"这一层不是锦上添花，是唯一能读到数的路。

## 做了什么

### 1. 采集内核（`internal/collector`）

- `pack.go`：采集包规范与**装载门禁**。`hosts` 必填且每个请求主机都要在声明内（重定向也拦）、
  只允许 http/https、只允许 GET/POST、模板占位符白名单（`{username}/{password}/{captcha}/{otp}/{site}`
  加前序步骤提取出的变量）、正则/字段名/未知顶层字段逐项校验、末了必须能取到 `balance` 或 `quota`
  —— 任一不满足直接拒绝装载，不做"猜一半"的宽容解析。
- `runner.go`：会话（Cookie 罐 + 变量 + 头）、`Run` 执行登录与读取、`ReadBalance` 四族协议之外
  的"任意站点"通路。失败原因码与 `internal/health` 同一套字符串，面板归组统计才能合并。
- `loginproxy.go`：把站点登录页反代到 octopus 自己的路径下；服务端捕获 `Set-Cookie`；
  改写 `href/src/action` 与 `Location`；去掉 `X-Frame-Options`/CSP；`Domain`/`Secure` 去掉、
  `SameSite=None` 降级 `Lax`；**我们自己的 `auth` Cookie 永不转发给上游**。

### 2. 落库与管理面

- 新表 `credential_sources`（`internal/model/credential_source.go`）：kind（login/pack）、site、channel_id、
  units、status、三类密文（pack/credential/session，AAD 分别是 `collector:pack`/`:credential`/`:session`）。
- `internal/op/credential_source.go`：CRUD、会话加解密、`CredentialSourceRunNow`（跑包 → 落读数 →
  绑定渠道时直接进余额管线）、`CollectorReadingForChannel`（供扫描用）、`CollectorLoginProxy`。
- `internal/server/handlers/collector.go`：`/api/v1/collector/*`（全部管理面鉴权），含登录代理本体。
- 扫描接线：`internal/task/quota_scan.go` 里**采集凭据优先于通用协议探测**（用户明确指定的读法更权威），
  并把"读到数之后"的告警与归零停表抽成 `handleQuotaReading` 给两条路共用 —— 只给其中一条接告警，
  会让"采集凭据读到的余额低于阈值"静默不报警。
- 文档：`docs/collector/README.md`（两条路怎么用、包字段速查、装载门禁、接口表、诚实边界）。

## 本轮实测抓到的四个缺陷（都已修 + 有判据）

1. **Cookie 罐按域取值，"导出会话"拿不到东西**：Go 标准库没有"把罐里所有 Cookie 倒出来"的接口，
   用探针域去问永远得到空集 —— 表现是"登录明明成功却被判成没有会话"。
   改成记录式 Cookie 罐（`SetCookies` 时顺手抄一份），导出与发请求用同一批 Cookie。
2. **采集客户端没挂 Cookie 罐**：交互登录拿到的就是 Cookie，不挂的话读取请求一路裸奔 → 站点回 401，
   用户看到的是"明明登录了却说没登录"。
3. **安全缺陷：管理会话被转发给上游**。原先只在"过滤后还剩别的 Cookie"时才覆盖 Cookie 头，
   于是浏览器只带 `auth` 一个 Cookie 时，原始头被整包转发 —— 等于把自己的管理会话送给第三方站点。
   实测证据：诊断桩收到 `Cookie: auth=eyJhbGci...`；修成无条件先删再按需设置，并补了两条用例
   （只带 auth / auth+其它 两种形态都不得泄漏）。
4. **转发正文丢掉 Content-Length**：Go 对未知长度的正文改用 chunked，不少站点按长度判空体，
   表现是"登录页能打开、提交却总说密码错"。改为透传原始长度。

## 验证证据

- 单测：`internal/collector` 14 例（包校验拒绝矩阵 12 项、JSON 路径/数字/模板、登录→用令牌读账全流程、
  登录 200 但无会话判 unauthorized、包与站点形状不符判 unparsable 且点名字段、未声明主机重定向被拒、
  代理捕获会话与地址改写、跨站重定向被拦、二进制响应不改坏、**管理 Cookie 不泄漏**、**Content-Length 透传**）；
  `internal/op` 4 例（三类密文落库且密码不出现在库里/出参不回显、美元与点数按 `units` 进管线不互相折算、
  停用不参与扫描、删除清行清会话）。全仓 `go build`/`go vet` 干净，`go test ./... -count=1` **20 包全绿**。
- 活体（本地实例 33000/33001，桩站 127.0.0.1:33911，脚本 `%TEMP%\octopus-dstest\verify_collector.py`）**13/13 通过**：
  - 交互登录路：建凭据 → 取临时地址 `/api/v1/collector/login/10/` → 反代登录页的 `action`/`src` 都被改写到前缀 →
    经反代提交登录得到 302 且 `Set-Cookie: sid=...; Path=/api/v1/collector/login/10/` → 完成登录后**试读余额 88.8**。
  - 采集包路：填账号密码 → 一步采集成功 `balance=88.8 currency=usd`，步骤轨迹
    `POST /api/login → 200`、`GET /api/user/self → 200`。
  - 绑定渠道 1 后触发余额扫描：渠道 1 余额 = 88.8（来自采集凭据），总余额 109.26 → 194.75 USD。
  - 测试凭据清理干净（remaining=0）。
