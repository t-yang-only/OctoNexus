# 2026-09-16 号池扩展层第九批：渠道凭据后端（中转站/反代站点）

## 1. 为什么是这一批

用户目标原话是「号池加入高度的扩展性…后面好可以进行各种反代工具包的扩展」，随后给出了他的站点清单
（`数据备份(勿提交).json`，只读、不入库、不进 git）。清单一读就清楚了两件事：

- 他要接的不是"某种软件"，而是**他自己的十几个中转站/反代站点**（53HK、longcat、OKai、THK…）；
- 这些站点的接口形态仓库里**已经有了**：`internal/health/relay_account.go` 写明了两族——
  New API 系（`POST /api/user/login` 拿 session，`GET /api/user/self` 查额度）与 S2 系
  （`POST /api/auth/login` + `/api/keys`、`/api/subscriptions`、`/api/platform/quotas`）；
  `internal/health/probe_token_client.go`、`balance.go` 还把"带 Authorization 打 /api/user/self"
  这条只读口径实现成了可复用函数。

所以这一批没有任何新协议、新表、新凭据存储：**把既有渠道凭据投影成号池条目**，把既有的健康/余额
客户端接到号池的生命周期操作上。

## 2. 形态：`kind=channel`（内置第二个适配器）

`internal/pool/station.go`：

- **条目 = 一个渠道下的每条凭据**，ID 是 `<channel_id>:<key_name>`（渠道 ID 是数字，按第一个冒号
  切分就能拆回来，凭据名里带冒号也不会歧义）；
- 名称 `渠道名 / 凭据名`，provider 是渠道名，labels 带 `channel/family/base_url`；
- **官方账号池自动物化的那几个渠道在这里排除**（`op.IsOfficialPoolChannelName`，前缀单一维护）：
  同一条凭据不能既有"账号"身份又有"渠道凭据"身份；
- 能力位 `list/get/probe/refresh/toggle`，**不声明 sync/provision/revoke**：这里没有任何东西需要
  被"物化"，凭据本来就是人配的；
- `Healthy` 用凭据自身的累计统计（成功数 ≥ 失败数），无样本按乐观先验记健康——与选路侧
  "缺数据不惩罚"同一口径，条目里写明 `healthy_basis`；**实时结论只能靠探活**，因为那是一次真实请求。

## 3. 三个动作分别落在既有实现上

| 动作 | 落点 | 口径 |
|---|---|---|
| probe | `health.ProbeToken(ctx, kind, baseURL, key, proxy)` | 站点族决定口径：`/v1` 结尾→`openai_key`（`/v1/models`）、含 anthropic→`anthropic_key`、其余→`na_token`（带 Authorization 的 `/api/user/self`）。口径写回 `detail.probe_kind`，免得看到"不健康"却不知道按哪套判的 |
| refresh | `health.FetchBalance(ctx, baseURL, key, proxy)` → `op.RecordChannelBalance` | 余额既回条目，也**落进渠道余额快照**——加权选路的 balance 维度读的就是它，号池里刷一次余额选路侧顺带受益 |
| toggle | `op.SetChannelKeyEnabled(nil, channelID, keyName, enabled)` | 同时写"是否参与选路"与"人工停用"，所以周期物化不会把人工停用悄悄改回启用（第六批修的正是这个坑） |

失败语义沿用既有约定：条目不存在 404、站点不健康/余额读不到 502 且**条目照回**（带当前快照与原因）。

## 5. 踩坑

- `/channel/create` 的 `models` 收的是"模型名字符串列表"这一形状，给 `[{"name": "x"}]` 会被判
  `Invalid JSON format`（400）——夹具改成 `models: []` 即可；
- 套件夹具命名要避开既有的"按 RUN_TAG 做名称子串过滤"的断言：新夹具叫 `POOLAPI-STATION-<时刻>`，
  刻意不含 `POOLAPI-<时刻>` 这个子串，否则 P2/P13b/P17/P18b 会集体变成假失败（口径没错，是过滤被污染）；
- 新增内置适配器会波及"枚举全部 kind"的老用例：`withoutBuiltin` 改成摘掉**全部**内置适配器，
  新增内置适配器时记得加进那个清单（否则单测会因为没初始化 DB 而 panic）；
- 单测里 toggle 会走 `op.SetChannelKeyEnabled` → 刷新渠道缓存 → 读授权表，所以内存库要一起
  AutoMigrate `channel_grants`。

## 6. 与用户清单的关系（如实说明边界）

- 这一批落地的是**凭据级**视图：每个渠道的每条 key 都能看健康/统计/余额、能探活、能启停。用的是
  站点对 **API key** 开放的只读端点，不需要任何账号密码；
- **账号级**视图（登录态下的订阅、平台配额、站点内 token 列表）需要站点的账号密码：仓库里
  `internal/health/relay_account.go` 的两族登录客户端已经具备，但 octopus 目前没有存这类账号的表。
  要不要引入（以及存哪里、怎么加密）是一个需要用户拍板的新面，不擅自实施；
- 全量测试矩阵与提交记录见台账。
