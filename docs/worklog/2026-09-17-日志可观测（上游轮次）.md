## 二、这一轮做了什么：日志记录「上游轮次」

**动机**（与本项目自己的排障需求一致）：用户给的线上日志包里，超时/挂起类问题的共同症状是
"这一条到底是上游慢，还是换人换出来的"——日志里只有总耗时和终态，看不出中间换过几次成员。
上游 #395 把这件事说成"重试详情"，维护者不做；但本项目已经有 `RequestState.Round`
（每轮上游请求递增，首字竞速的多路并发算一轮），把它落到日志里是一行的事。

| 位置 | 改动 |
| --- | --- |
| `internal/model/log.go` | 新增 `Attempts int json:"attempts"`：1 = 第一次就出结果，>1 = 中途换过成员，0 = 还没发起上游就结束（分组不存在/成员解析失败） |
| `internal/relay/state.go` | 终态快照写入 `Attempts: r.Round`（与面板"第几轮"同源，同口径） |
| `internal/op/log_export.go` | 导出列新增「上游轮次」（插在「耗时(ms)」与「输入tokens」之间，错误列移到最后一列） |
| `web/src/components/modules/log/*` | `display.ts` 的 `LogDisplayFields.attempts`（历史行取落库值，在线快照取 `round`）、`store.ts` 字段可见性（默认可见）、`FilterBar.tsx` 字段开关、`Item.tsx` 单元格（图标 + 数值）、三语文案 `attempts` |
| `scripts/api-tests/run_retry_test.py` | 新增 R10：耗尽上限的请求记 6 轮、换人成功的请求记 2 轮 |
| `scripts/api-tests/run_panel_asset_test.py` | 新增 P10：字段键被界面引用 + 三语文案进产物 |

**为什么不做成"完整重试详情"**（与上游一致的取舍）：把每一轮的成员、错误、耗时都记下来意味着
一张日志行拆成多行或新增子表，代价是库体积与查询复杂度；而排障要回答的两个问题——
"换没换人"（`attempts`）与"慢在哪一段"（`first_byte_ms` / `duration_ms`）——一行就能答。

## 四、边界与未覆盖

- `attempts` 记的是**轮次**，不是 HTTP 尝试次数：首字竞速同时发多路，仍然算一轮（与面板同口径）。
- 不记录"每一轮分别打到谁/失败原因"，那需要新的子表（见第二节的取舍）。
- 流式请求走同一个终态快照路径，但没有单独的用例断言其 `attempts`（非流式的 R10 覆盖了读写链路）。
