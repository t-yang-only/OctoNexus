# 首字竞速（T-hedge-001）实现与「真实上游测试门禁」

日期：2026-09-16　执行：dsh-local（NM-DS-016）
需求来源：用户指令（2026-09-16）「在高峰期，或者在突然唤醒开始调用的时候，同时在选择的分组里面请求置顶的多个 API，得到最优的首字」，
并在同一条指令里要求「不要在空闲时间使用 api 进行测试」。设计稿：`docs/research/2026-09-16-T-hedge-001-首字竞速设计稿.md`。

## 1. 先落门禁：测试默认不再碰真实上游

用户明确要求不做"空闲时间拿真实 API 测试"。改动：

- `scripts/api-tests/run_all.py`：套件清单里给会打真实上游的 `real`、`costmode` 打上 `real` 依赖标记；
  默认**跳过**并打印「跳过真实上游套件（默认不透支额度）: …」；需要时显式 `--with-real` 或 `OCTOPUS_ALLOW_REAL=1`。
- `run_real_tests.py` / `run_costmode_test.py`：套件自身也加门禁，单独跑而没开开关时直接
  `SKIPPED: this suite calls real upstreams and costs money; set OCTOPUS_ALLOW_REAL=1 …` 退出（退出码 0，不是失败）。

效果实测：`python run_all.py --only real,costmode,format` → 只跑 format（11/11），real/costmode 被跳过；
单独 `python run_real_tests.py` → 直接 SKIPPED。带 `OCTOPUS_ALLOW_REAL=1` 时放行（验证过一次通道可用）。

## 2. 首字竞速（提交首字节之前，并发请求排序靠前的多个成员）

### 2.1 行为

| 触发条件 | 配置键 | 说明 |
| --- | --- | --- |
| 慢启动（冷启动 / 被限速） | `hedge_after_ms`（默认 800）| 首选成员在该毫秒数内没给出首个有效响应，就追加并发请求次选成员 |
| 高峰期 | `hedge_peak_in_flight`（默认 0=关）| 该分组在途请求数达到该值时**立刻**并发（不等延迟阈值）|

- 并发路数 `hedge_width`（含首选，2..5，默认 2）；候选顺序沿用该分组当前模式的排序，首选一定是第一名。
- 任一路先给出有效响应即胜出，其余立刻取消；**客户端已收到字节后不再切换**（与"首字节提交后不可重试"一致）。
- **落选成员不算失败**：不进冷却、不记失败、不污染质量/延迟样本（它是被我们自己取消的）。
- 默认关闭：竞速意味着同一份输入可能被多个上游各处理一次，上游按 token 计费时最坏付 width 份钱。

### 2.2 实现

- `internal/relay/hedge.go`（新）：`hedgeSettingsOf`（读配置+夹紧边界）、`prepareRoundTarget`（把一路尝试所需的成员/渠道/凭据/出站配置
  准备成**独立请求副本**——`applyChannelConfig` 会改写 Body/JSONBody/Headers，共享同一份在并发下会数据竞争）、
  `cloneHTTPRequest`、`rankedHedgeCandidates`（复用现有各模式 ranker 拿到有序候选）、`groupInFlight`、
  `runRoundWithHedge`（并发跑主路与竞速路，首个成功者胜出，其余取消；全部失败时返回主路错误以保留既有重试/冷却语义）、`logHedge`。
- `internal/relay/handler.go`：把每轮的"成员解析 + 出站准备 + 单路发送"抽成 `prepareRoundTarget` + 竞速感知的尝试块。
  **未开启竞速时走原单路分支，代码与语义与改前一致**（既有 failover/probe/format 套件全部通过即为回归证据）。
- `internal/relay/state.go`：新增 `inFlightByModel`（按客户端模型名=分组名统计在途，复用 least_busy 的活动请求注册表，
  结构上不可能漏释放）与 `retargetRound`（竞速胜出后把本轮目标改成胜者，不递增轮次）。
- `internal/model/group.go`：`GroupRelayConfig` 增补 `hedge_enabled` / `hedge_width`(2..5) / `hedge_after_ms` / `hedge_peak_in_flight`(0..64)，
  默认值与归一化随开启状态生效（未开启保持全零，不影响任何既有分组）。
- 观测：每次竞速打一行 `hedge group=… primary=… winner=… loser=… waited=…ms`，便于事后算"多花的钱换回了多少首字"。

### 2.3 验证（**全部走本地 mock，未打真实上游**）

新增 `scripts/api-tests/run_hedge_test.py`，5/5 通过：

| 用例 | 结果 |
| --- | --- |
| T1 竞速开启（首选 mock-slow 上游 sleep 15s，次选 mock-good）| **0.8s** 由快成员返回；mock 侧确认收到 `['mock-slow','mock-good']` 两路 |
| T2 关闭竞速对照组（同顺序）| **15.0s** 走完慢成员，行为与改前一致 |
| T3 落选成员不进冷却 | 竞速后分组 `runtime.cooldowns` 为空 |
| T4 高峰期在途触发（`hedge_peak_in_flight=1`）| **0.0s** 立刻并发、快者胜出，mock 侧两路都在 |
| T5 `hedge_width=9` | 400（校验 2..5）|

回归：全量矩阵（含新 hedge 套件）通过；`go build ./...` / `go vet ./...` 退出码 0；`go test ./... -count=1` 全绿。
