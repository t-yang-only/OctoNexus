# 余额采集扩展包开发指南（R-ext-002）

> 面向「想让 octopus 读到某个新中转站余额」的人。
> 前置阅读：`docs/collector/README.md`（采集包字段速查与装载门禁）、`docs/extensions/README.md`（三类扩展总览）。
> 本文只讲**怎么把一家新站点做成扩展包**，以及**怎么把它交给别人**。

---

## 一、扩展包是什么

octopus 的余额有两层来源：

| 层 | 怎么读 | 适用面 |
|----|--------|--------|
| API 层 | 四族协议探测（`/user/balance`、`/usage`、`/api/user/self` 等） | 只有少数站点能用 |
| **账号层** | **登录会话 / 采集包** | 绝大多数站点 |

**采集包（Pack）就是账号层的「扩展包」**：一份 JSON，描述

- 允许访问哪些主机（`hosts`）
- 怎么登录拿会话（`login`）
- 拿会话之后按什么路径、什么口径读余额（`read`）

它是**数据而不是代码**——所以可以写一份、复制给别人、别人只改账号密码就能用。

---

## 二、五步做出一个采集包

### 第 1 步：先确认站点有没有可读的余额接口

不要凭页面猜。按顺序试：

```bash
# ① 有没有公开的模型广场（有价格页通常也有账户接口）
curl -s https://SITE/api/v1/settings/public | head -c 400

# ② 常见路径探一遍（用你自己的 key 或先登录拿到的 token）
curl -s -H "Authorization: Bearer $TOKEN" https://SITE/api/user/self
curl -s -H "Authorization: Bearer $TOKEN" https://SITE/api/v1/user/profile
curl -s -H "Authorization: Bearer $TOKEN" https://SITE/api/v1/user/balance
```

**判据**：拿到带余额数字的 JSON，且能确认**这个数字是剩余还是总额**（见第六节第 1 条）。

### 第 2 步：浏览器真实登录，抓真实请求

**这是唯一可靠的方法**。静态 grep 前端 bundle 提不到——URL 是运行时拼接的（实测 6 个站点全部提不到）。

1. 打开站点，F12 → Network → 勾选 `Preserve log`
2. 正常登录一次
3. 找到**登录请求**（记下 URL、方法、请求体形状）
4. 找到**读账请求**（记下 URL、请求头里带的是 Cookie 还是 `Authorization: Bearer`）
5. 特别留意：**会话令牌往往在登录响应的 JSON 里**（如 `data.access_token`），不在 Cookie 里

### 第 3 步：写出采集包 JSON

最小可用骨架：

```json
{
  "name": "示例站点",
  "version": "1",
  "units": "usd",
  "hosts": ["api.example.com"],
  "login": {
    "mode": "form",
    "url": "/api/user/login",
    "body": "{\"username\":\"{username}\",\"password\":\"{password}\"}",
    "extract": [{ "field": "token", "from": "json", "path": "data.access_token" }]
  },
  "read": [
    {
      "name": "账户余额",
      "url": "/api/user/self",
      "headers": { "Authorization": "Bearer {token}" },
      "extract": [{ "field": "balance", "from": "json", "path": "data.quota" }]
    }
  ],
  "notes": "写清楚口径依据，例如：data.quota 就是剩余额度本身"
}
```

### 第 4 步：装进 octopus 并验证

面板 → **扩展** → **采集凭据** → 新增 → 粘贴上面的 JSON → 填账号密码 → 保存。

然后看**首页的总余额**里这个渠道是否从「未读到余额」变成有数字。

### 第 5 步：分享给别人

见第七节。

## 三、字段速查

### Pack（顶层）

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | ✅ | 包名（展示用） |
| `version` | | 版本号，建议分享时递增 |
| `units` | | `usd`（默认）/ `points`。**决定读数要不要按 `balance_points_per_unit` 折算** |
| `hosts` | ✅ | 允许访问的主机白名单。**请求与重定向都不得越界（fail closed）** |
| `login` | | 登录规格；没有登录（纯 key 读账）可省 |
| `read` | ✅ | 读数步骤数组 |
| `notes` | | 给未来自己/别人的说明，**建议写清口径依据** |

### LoginSpec

| 字段 | 说明 |
|------|------|
| `mode` | `form`（默认，接口登录）/ `interactive`（反代登录页，人工过一次验证码） |
| `url` | form 模式的登录接口地址（相对站点的路径） |
| `method` | 默认 `POST` |
| `body_type` | `json`（默认）/ `form` |
| `body` | 正文模板，支持 `{username}` `{password}` `{captcha}` `{otp}` `{site}` |
| `headers` | 额外请求头（可含模板） |
| `extract` | 从**登录响应**里捞变量（如 `token`） |
| `need_captcha` | 置 true 时面板提示「需要人工给验证码」 |

### ReadStep

| 字段 | 说明 |
|------|------|
| `name` | 步骤名（展示用） |
| `url` | 请求地址（相对路径） |
| `method` | `GET`（默认）/ `POST` |
| `body_type` / `body` | 需要 POST 时使用 |
| `headers` | 请求头，可引用上一步捞到的变量：`Bearer {token}` |
| `extract` | 取值规则 |

### ExtractRule

| 字段 | 说明 |
|------|------|
| `field` | 取到之后叫什么。**`balance` / `used` / `quota` / `currency` / `username` / `note` 会被识别为「账」，其余名字一律作为变量留给后续步骤**（如 `token`） |
| `from` | `json`（点号路径 `data.items.0.balance`）/ `regex` / `header` / `status` |
| `path` | json 路径，或响应头名 |
| `regex` / `group` | `from=regex` 时使用；`group` 默认 1，0 表示整个匹配 |

### 占位符

- 凭据占位符：`{username}` `{password}` `{captcha}` `{otp}` `{site}`
- **变量占位符**：`{token}` 一类由 `extract` 捞出的名字，**在 `read` 步骤里可直接引用**
- `token` 在采集包占位符白名单里**无条件允许**——现代站点普遍用它而不是 Cookie

## 四、三类站点的实战打法

### 类型 1：new-api / one-api 系（接口同源）

**特征**：`POST /api/user/login` + `GET /api/user/self`，额度单位是**点**。

内置模板 `new-api` / `one-api` 已覆盖，直接用模板再改站点域名即可。

**两个必须知道的点**：

- 新版本登录响应带 `access_token`，而 `/api/user/self` **只认 `Authorization: Bearer`**——只带 Cookie 读不到额度。
- `data.quota` **就是剩余额度本身**，不是总额度。

### 类型 2：自研 SPA 网关（登录换 token）

**特征**：没有 new-api 的接口；前端是自研 SPA；`/api/pricing`、`/api/models` 全部 404。

**打法**：抓它的登录接口，从响应体里捞 `data.access_token`（或等价字段），带着它读 `/api/v1/user/profile` 一类的路径。

```json
{
  "name": "AI Gateway（SPA 网关）",
  "units": "usd",
  "hosts": ["api.example-gw.com"],
  "login": {
    "mode": "form",
    "url": "/api/v1/auth/login",
    "body": "{\"email\":\"{username}\",\"password\":\"{password}\"}",
    "extract": [{ "field": "token", "from": "json", "path": "data.access_token" }]
  },
  "read": [
    {
      "name": "账户余额",
      "url": "/api/v1/user/profile",
      "headers": { "Authorization": "Bearer {token}" },
      "extract": [
        { "field": "balance", "from": "json", "path": "data.balance" },
        { "field": "currency", "from": "json", "path": "data.currency" }
      ]
    }
  ],
  "notes": "登录响应体里的 access_token 是唯一凭据；Cookie 无效。units=usd，不要再折算。"
}
```

### 类型 3：有验证码 / 无接口的站点

- **有验证码**：`login.mode` 用 `interactive`，走反代登录页，人工过一次验证码，之后靠会话复用 + `refresh_token` 续期（**53HK 与 apikey.fun 的 `POST /api/v1/auth/refresh` 实测不需要验证码**）。
- **完全没有余额接口**：不要硬编造，用**手动订阅**兜底（面板 → 首页 → 手动订阅），按点数口径手录，一样计入总额。

## 五、交付前的验证清单

一个采集包算「做完」，必须全过：

1. **装载门禁**：`hosts` 写全了——请求与重定向都不越界（越界即拒绝，fail closed）。
2. **登录成功**：能拿到会话（form 直登，或 interactive 人工过一次后会话可用）。
3. **读到数字**：余额从「未读到」变成具体数值。
4. **口径自证**：写清 `data.quota` 这类字段**是剩余还是总额**，并说明依据（哪次实测、什么现象）。
5. **单位自证**：`units` 是 `usd` 还是 `points`——**填错会让余额差 50 万倍**。
6. **出口策略**：站点需要走节点时，`proxy_node_id` 指到节点；**出口不可用要拒绝采集，不许静默直连**（会把真实 IP 暴露给站点）。
7. **回归用例**：若同时改了后端代码，必须补对应的活体用例（本项目惯例见 `scripts/api-tests/run_balance_test.py`）。

## 六、踩过的坑

### 1. `quota` 到底是剩余还是总额——只能实测

new-api 的 `data.quota` **是剩余额度本身**。把它当「总额度」再减 `used_quota`，会算出 **-187900000 点 ≈ -375.8 USD** 这种负数余额——数字看着「有值」，极易被当成读到了。

**做法**：直接读 `quota` 当余额，绝不走「总额度 − 已用」的推导分支。

### 2. 会话在响应体里，不在 Cookie 里

现代中转站（new-api 与同源 SPA）的会话是**响应体里的 `access_token`**。

- 读账必须 `Authorization: Bearer {token}`
- 反代登录页也必须**从流经代理的 JSON 响应里捞令牌**进会话变量

否则会出现「页面登录成功、采集却 401」。

### 3. 「页面上看得到价格」≠「能 curl 到价格」

SPA 渲染型站点 curl 回来的 HTML 只是空壳（实测 56749 字节，与首页同尺寸），正则解析得到 0 条。

**动手前先判断页面是接口渲染还是 SSR**，否则会在解析上白费一轮。

### 4. 保存路径漏字段 = 接口 200 但库里没变

新增可写字段时，字段写在别的分支条件里（如 `if in.Site != ""`），或 Update 的 `Select(...)` 列清单漏列，都会造成**「接口返回 200 但库里没变」**。

**做法**：新增可写字段必须同时补回归用例。

### 5. 保存路径的另一个分支：`protocols` 位

渠道授权的 `protocols` 是位掩码：**`1<<1=2` chat / `1<<2=4` responses / `1<<3=8` messages**，合法全集 `14`。

**bit0 不是有效位**——传 `1` 会被拒绝（`channel grant protocols 1 is empty or contains undefined bits`）。本项目 `run_balance_test.py` 曾因此失败（2026-09-22 已修）。

## 七、分享给别人

### 现在：复制 JSON

采集包是**纯数据**，分享 = 把 JSON 给出去。接收方：

1. 面板 → 扩展 → 采集凭据 → 新增
2. 粘贴 JSON
3. **只改自己的账号密码**（JSON 里不含凭据——`{username}` / `{password}` 是占位符）

**分享前请自检**：JSON 里不能出现任何真实账号、密码、token、SendKey。

### 规划中：导出 / 导入 / 包注册表

缺口已记录在 `docs/extensions/README.md` 的「诚实边界」：

- **导出/导入**：把一份采集包导出成文件、别人导入后只填凭据
- **包注册表**：列出可用包、按站点推荐

接口预留：在既有 `/api/v1/collector/sources` CRUD 与 `/templates/{list,render}` 旁边加 `export` / `import` 与 `registry` 两个端点即可，**不要另造一套体系**。
