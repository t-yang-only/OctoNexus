# 本轮吸收同类项目优点的四项能力

> 面向：想知道"这四个功能解决什么问题、口径是什么、怎么验"的人。
> 背景：本轮对照上游 [lingyuins/octopus](https://github.com/lingyuins/octopus)（v2.6.0）、
> [New-API](https://github.com/QuantumNous/new-api)、[One-API](https://github.com/songquanpeng/one-api)、
> [all-api-hub](https://github.com/qixing-jk/all-api-hub) 做了功能面对比，挑出四项性价比最高的补齐。

---

## 1. 模型映射（Model Mapping）

**解决什么**：客户端写死带版本后缀的模型名（`claude-3-5-sonnet-20241022`），
本地分组名却是简名（`claude-sonnet`），客户端因此拿到 `model not found`，
只能为每个版本后缀各建一个分组。

**口径（只有一条，刻意不做多义）**：规则命中客户端的请求模型名时改写成目标分组名，
再按改写后的名字找分组。**未命中任何规则时逐字保持原名**——这是升级安全性的分水岭，
没配规则的项目行为与改造前完全一致。

**三种匹配**：`exact`（整名，忽略大小写）/ `wildcard`（`*` 与 `?`，点号是普通字符）/
`regex`（标准语法）。数字越大越先匹配。

**刻意不做的**：上游的 `ScopeGroupID`（按分组作用域改写发往上游的模型名）。
那属于另一件事，与本表"定位本地分组"的职责混在一起会让两条链路都难排查。

**怎么验**：
- 面板 → 设置 → 路由策略 → 模型映射 → 「试一下」：输入一个客户端会发的模型名，
  立刻看到改写成什么、命中了哪条规则（保存前后都能试）。
- 活体套件：`python scripts/api-tests/run_model_mapping_test.py`（M1-M6）

## 2. 用量报告（Usage Reports）

**解决什么**：接了几十家上游之后，"这个月花了多少、哪家最贵、哪家在掉成功率"
只能靠人翻面板。

**三条口径**（都是为了让发出来的数字"看过就不再变"）：
- 只描述**已落库的统计**，正文标出数据截止时间；
- 覆盖**上一个完整周期**（日报＝昨天、周报＝上一自然周、月报＝上一自然月）；
- 同一个周期只发一次（周期键落库，重启/重复触发都不补发）。

**两个如实性细节**（都是实测踩出来的）：
- 总计来自逐日统计、排行来自小时明细桶，两者保留期不同，会出现"总数一万多、
  排行只有 3 次"的矛盾——正文会写明明细覆盖量；
- 没扫到任何渠道余额时输出"未知"而不是 `0.00`（印 0 会被看成"没钱了"，
  违反项目既有口径 T-balance-001）。

**怎么验**：
- 面板 → 设置 → 通知 → 用量报告 → 「预览」（空周期与非空周期两条路径都试一遍）
- 活体套件：`python scripts/api-tests/run_usage_report_test.py`（R1-R6）

## 3. 告警规则（Alert Rules）

**解决什么**：本项目本来就会在**具体事件**上发通知（余额归零、探活恢复）。
失败往往是散落的，没有单一事件可以挂钩，只能按指标判定。

**两条防噪音机制**——这是这套东西能不能用的分水岭：
- **样本量下限**：窗口内请求数低于 `min_requests` 一律不判定。
  没有它，一次偶然失败会被算成 100% 错误率，这是告警系统最常见的噪音来源；
- **冷却按「规则 + 渠道」独立**：同一规则同一渠道在冷却期内不重复触发；
  一个坏渠道不会吃掉别的渠道的告警名额。

两条都做了变异检查：去掉守卫 → 对应用例立刻变红。

**怎么验**：
- 面板 → 设置 → 通知 → 告警规则：每条规则上的「试算」会回答"**现在**会不会报、
  为什么"（`会触发` / `未越阈值` / `样本不足，不判定` / `冷却中，不重复报`）
- 活体套件：`python scripts/api-tests/run_alert_rule_test.py`（A1-A7）

## 4. 客户端配置导出（Client Config Export）

**解决什么**：把网关接好之后，还得知道"客户端该怎么配"——base URL 填什么、
key 填哪把、model 填什么。这三样在面板上分散在三处，而各客户端要的格式又不同。

**比上游多两样**（都是实际配过之后才知道缺的）：
- **带上模型名（分组名）**：只给 base URL 与 key 不够——客户端还得知道请求哪个模型名；
- **给出配置文件形态**：只给环境变量在 Codex 这类用 `config.toml` 的工具上不够用。

**每个目标的易错点都写进正文**（客户端对这类错配只会报含糊的连接失败）：

| 客户端 | 易错点 |
|--------|--------|
| Claude Code | 用 `ANTHROPIC_AUTH_TOKEN` 而不是 `ANTHROPIC_API_KEY`（后者不发 Authorization 头） |
| Codex CLI | `base_url` 必须以 `/v1` 结尾；`wire_api = "chat"`；key 走环境变量不进配置文件 |
| Gemini CLI | `GEMINI_API_KEY` 填的是网关 Key；base URL 变量名随版本不同 |
| Cherry Studio | 图形界面，给字段清单；地址要带 `/v1`，模型名不会自动同步 |
| OpenAI 兼容 | base URL 带 `/v1`，路径不要再重复写 `/v1` |

**安全**：导出内容含 Key 明文（那正是它有用的原因），接口挂在管理面鉴权之内，
活体套件 E1 专门验匿名不可用。

**怎么验**：
- 面板 → 设置 → API 配置 → 客户端配置导出
- 活体套件：`python scripts/api-tests/run_cli_export_test.py`（E1-E5）

## 还没做的（诚实清单）

按性价比排序，这些是同对比里我们仍然缺的：

1. **WebDAV 云备份** —— 本地面板已有备份/恢复，云端那份还没有
2. **RBAC（admin / editor / viewer）** —— 当前是单管理员模型
3. **API Key 治理增强** —— IP / CIDR 白名单、每模型配额
4. **站点管理（多账号 / 自动签到）** —— 上游 lingyuins 有，我们只做到了采集凭据层
5. **语义缓存（embedding）** —— 上游有完整实现
6. **运行时状态持久化** —— 冷却与熔断状态目前在内存，重启即清空
7. **WebAuthn / Passkey 登录**
8. **活动热力图 / 可配置导航** —— 纯展示层

判断依据：前四项是"能省事或能保命"的，后四项是"锦上添花"。
