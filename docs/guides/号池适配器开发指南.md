# 号池适配器开发指南

> 面向"想把别的工具包接进 octopus 号池"的人。读完这一页你能写出一个通过契约自检的适配器；
> 需要单独决策的部分（运行时声明式注册）在文末标清楚了。

## 1. 号池扩展层是什么

octopus 的号池不是"一种账号表"，而是一个**可插拔的后端集合**：每个后端（kind）自己声明
「我能做什么」，接口层按声明放行；外部工具包靠自描述发现后端，不必读 octopus 源码。

```
外部工具 / 面板
      │  统一视图 + 自描述 + 能力位放行的操作
      ▼
internal/pool   注册表 Registry ── Adapter（一种后端一个实现）
      │                                  │
      │                                  └── official：官方账号池（内置）
      ▼
internal/op     渠道 / 渠道凭据 / 模型授权 / 选路
```

**关键约束：适配器只做投影。** 它把某个后端的状态投影成统一视图的行（`pool.Entry`），
写操作按能力位逐个实现。选路、渠道物化、凭据加密这些事仍然归既有链路，适配器不碰。

## 2. 最小可用适配器

只有两个方法是必须的（`pool.Adapter`）：

```go
type Adapter interface {
    Info() AdapterInfo
    Entries(ctx context.Context) ([]Entry, error)
}
```

可运行示例在 `internal/pool/pooltest/example_adapter_test.go`（同时是本文档的代码样本，
由 CI 编译和运行，不会失修）：

```go
type inventoryAdapter struct {
    baseURL string
    token   string // 凭据刻意不放进 Entry
}

func (a *inventoryAdapter) Info() pool.AdapterInfo {
    return pool.AdapterInfo{
        Kind:         "example-inventory",
        Title:        "示例：外部工具包账号清单",
        Capabilities: []pool.Capability{pool.CapList, pool.CapGet, pool.CapProbe},
        Fields: []pool.FieldSpec{
            {Name: "base_url", Type: "string", Label: "站点地址", Required: true},
            {Name: "access_token", Type: "string", Label: "访问令牌", Required: true, Secret: true},
        },
    }
}

func (a *inventoryAdapter) Entries(ctx context.Context) ([]pool.Entry, error) {
    if err := ctx.Err(); err != nil { return nil, err }
    return []pool.Entry{{
        Kind: "example-inventory", ID: "acc-1", Name: "示例账号",
        Provider: "example", Status: "active", Enabled: true, Healthy: true,
    }}, nil
}
```

## 3. 能力位与对应接口

声明了某个能力位，**就必须实现对应接口**（`pooltest` 会把"声明了没实现"判为失败；
运行时会容忍它并回 501，那是给"先接只读、后补写操作"留的渐进口子，不是给接完就忘留的）。

| 能力位 | 需要实现的接口 | 对外路由 | 语义 |
|---|---|---|---|
| `list` | `Entries`（必需） | `GET /pool/entries` | 列出条目 |
| `get` | `Get(ctx, id)` | `GET /pool/entries/{kind}/{id}` | 按 ID 取单条 |
| `probe` | `Probe(ctx, id)` | `POST .../probe` | 主动探活 / 读配额 |
| `refresh` | `Refresh(ctx, id)` | `POST .../refresh` | 刷新凭据（换新 token） |
| `toggle` | `SetEnabled(ctx, id, bool)` | `POST .../enable`\|`/disable` | 人工启停 |
| `sync` | `Sync(ctx)` | `POST /pool/kinds/{kind}/sync` | 物化到转发层 |
| `provision` | （预留） | — | 新建条目（授权链接/扫码/登录） |
| `revoke` | （预留） | — | 删除/撤销条目 |

`pool.AllCapabilities()` 是权威清单；`pool.KnownCapability(c)` 用来校验传入值。

## 4. 契约自检（接入方的标准动作）

```go
func TestMyAdapterContract(t *testing.T) {
    pooltest.Run(t, &MyAdapter{})        // 有问题直接让测试失败，一次列出全部
}

problems := pooltest.Check(ctx, adapter)  // 想自己处理问题列表时用这个
```

检查项（每条都有反例测试，见 `internal/pool/pooltest/pooltest_test.go`）：

1. `Kind` 非空、能力位合法且不重复、必须声明 `list`；
2. **声明了能力位就必须实现对应接口**；
3. 字段自描述：名字非空、不重复；
4. **条目身份**：ID 非空且不重复、`kind` 回填成自己的 kind（ID 重复会让外部工具打错目标）；
5. **凭据不外泄**：标了 `secret` 的字段名不许出现在条目的 `Labels` / `Detail`（含嵌套一层）；
6. **列表与详情一致**：列表给的 ID 用 `Get` 必须取得到；不存在的 ID 必须报错
   （回一个空条目会让上层把"没了"显示成"活着"）；
7. `Entries` panic 被兜成可读问题，不带走测试进程。

## 5. 注册

编译期内置（当前唯一支持的姿势）：

```go
func init() {
    if err := pool.Register(&MyAdapter{}); err != nil {
        log.Fatalf("注册号池适配器失败: %v", err)
    }
}
```

`Register` 的护栏：空 kind、缺 `list`、未知能力位、重复 kind 都会被拒。

> **运行时声明式注册**（`POST /pool/adapters`：一份 JSON 描述一个后端，不改代码接入）
> 目前**没有开放**。它等价于"让 octopus 按外部给的规格去请求外部地址"，安全边界必须由使用者拍板
> （仅本地 / 域名白名单 / 不限），所以这一条在决策落定前不实现。

## 6. 错误语义（对外契约，别自己改）

| 情况 | 状态码 | 消息形如 |
|---|---|---|
| kind 未注册 | 404 | `unknown pool kind: xxx` |
| 条目不存在 | 404 | `entry not found` |
| 条目在、但此刻状态不允许该操作 | 409 | `pool entry state does not allow this operation: ...` |
| 后端没声明该能力位 | 501 | `capability not supported by this pool kind: toggle` |
| 上游/后端失败（含探活失败） | 502 | 适配器自己的错误原文 |

**404 与 409 别混用**：404 是"这条不在池子里"，409 是"它在，但现在做不了这件事"
（例如官方账号池的凭据还没物化出来）。外部工具靠这个区分决定"等下一次同步"还是"报错给人看"。

**探活失败不是 500。** 后端不可用是正常业务状态，要有可读的原因，也要能把条目当前状态一起回。

## 7. 常见坑

- **不要在 `Entries` 里做重活**：统一视图会被面板/工具频繁拉取。要缓存就自己缓存，
  但要保证"池子空"与"后端坏了"可区分（后者返回 error，会进 `warnings[]`，接口仍 200）。
- **一个后端坏掉不该让整张表消失**：单后端失败进 `warnings[]`；
  批量动作里也是一条失败不影响其余（逐条带原因）。
- **上下文**：`Entries`/`Get` 应当尊重 `ctx`（取消要快速返回）。
- **GORM 默认值坑**：带 `gorm:"default:true"` 的零值字段在 `Create` 时会被写成列默认值，
  默认值要放在入口层（指针字段区分"没给"和"给了 false"）。内置适配器踩过这个坑。
- **凭据回显**：任何接口、任何日志、任何导出都不许出现凭据内容。
  测试里建议用一个可识别串（如 `cipher-probe-<随机>`）写进库里，断言它不出现在响应报文里
  ——活体套件 `scripts/api-tests/run_pool_api_test.py` 就是这么做的。
