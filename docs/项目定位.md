# 项目定位（OctoNexus）

> 一句话：**OctoNexus 是一个独立项目**，代码血缘来自 [bestruirui/octopus](https://github.com/bestruirui/octopus)，
> 但在 GitHub 上**不是 fork 网络成员**（`fork=false`，无 parent/source），有自己的仓库、发布件、更新通道与演进路线。

## 1. 仓库身份

| 项 | 值 |
| --- | --- |
| 本项目仓库（`origin`） | `https://github.com/t-yang-only/OctoNexus` |
| 上游参考（`upstream`，**只读参考**） | `https://github.com/bestruirui/octopus` |
| 本地分支 | `master`，跟踪 `origin/master` |
| 许可 | **AGPL-3.0**（与上游一致，`LICENSE` 全文沿用；派生作品必须保持同一许可） |

remote 约定（2026-09-18 起）：

- `origin` = **本项目仓库**。默认的 `git push` / `git fetch` 都走这里。
- `upstream` = 上游仓库，**只作为参考**：用来对照上游 PR/issue、按需取上游修复。
  不要把本项目当成分叉去"跟进"上游：我们的 `master` 已经比上游多出上百个提交，行为口径以本仓库为准。

## 2. 与上游的关系（基于什么、升级了什么）

- **血缘**：上游 [bestruirui/octopus](https://github.com/bestruirui/octopus) —— Go 后端 + React 面板的 LLM API 聚合网关。
  文件名 `OctoNexus` = `Octo`（取自 Octopus）+ `Nexus`（枢纽）。
- **本项目的演进**：在保留上游既有模式行为不变的前提下，逐项升级为自用网关。已交付的能力与判据逐条记在
  [`docs/worklog/`](worklog/README.md) 与 [`docs/agents/ledger.md`](agents/ledger.md)，其中体量最大的几块：
  - 选路：智能路由显式档位（`smart` + 成员 `SmartTier`）、额度分压（`allocate`，按剩余请求数最优分配）、
    加权/成本/质量/延迟/最忙等既有模式的缺陷修复；
  - 限流与速度：429 带提示立即换成员 + 冷却封顶、成员自限流、逐成员首帧/吞吐量测与自适应首帧看门狗；
  - 余额：总余额聚合口径（含手动订阅并入）、标准协议余额端点；
  - 号池：官方账号池 + 渠道凭据池 + 运行时声明式适配器（白名单 fail closed、只读能力位）；
  - 安全：渠道凭据静态加密（`enc:v1:`，密钥文件丢失即解不开）；
  - 部署：单二进制发布件 + 一条命令升级/回滚 + 上线自检脚本；
  - 质量：34 套活体矩阵 + 单测/变异检查（改哪块必须同步对应判据，见各条记忆与台账备注）。
- **上游同步策略**：`git fetch upstream` → 逐条评估（上游 issue/PR 与本地是否同源）→ 只取最小切片 →
  **既有模式行为逐字不变**（新行为一律"新模式/新字段/新设置项"，不改变老路径语义）→ 同步判据矩阵。
  历史对照记录见 `docs/agents/需求登记.md` 的 `R-upstream-*` 条目。

## 3. 发布与更新通道（本项目自己的）

- 版本号唯一源头：`main.go` 的 `// Version`；构建命令与随件清单见 [`docs/deploy/`](deploy/)。
- 发布件：`D:\奇怪的软件\octopus-本地数据\release-<版本>\`（仓库外）—— 单二进制 + `SHA256SUMS.txt` +
  `build-record.txt` + 运行手册 + key 轮换清单 + systemd 单元 + `verify.sh`。
- **内置更新器指向本项目仓库**（`internal/update/update.go` 的 `updateOwner/updateRepo`），
  不再指向上游：否则产品里的"检查更新"会把上游的原版二进制装进来，等于把本项目上百个提交一次性抹掉。
  改动这条口径必须同步 `internal/update/update_test.go`（断言更新源是本项目、且不是上游）。
- 要让"检查更新"真正可用，本项目发布 release 时资产命名必须是 `octopus-<os>-<arch>.zip`
  （与 `internal/update/core.go` 的资产名规则一致）；在发布第一个 release 之前，检查更新会明确报"没有可用版本"，
  这是**预期**行为，不是故障。
- 上线必须人工替换二进制（本项目的发布件不进任何自动升级通道），步骤见 `docs/deploy/`。
